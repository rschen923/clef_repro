# 第一章　方案总览

## 1.1　项目归属、数据来源与所服务的研究问题

### 1.1.1　项目归属

本方案是研究报告《基于跨模态对比学习提升生物学优质标注稀缺条件下下游数据的效率与泛化》的配套实验实现，为**华东理工大学「人工智能技术与应用」课程的课程作业**，作者 `rschen923`。

其中 **CLEF**（**C**ontrastive **L**earning of **L**anguage **E**mbedding and Biological **F**eatures）是本作业中**自行设计并实现的**框架名，并非第三方已发表方法，目前无对应公开论文。其对比目标直接继承自 CLIP 的对称形式，但把「图像—文本」两模态替换为「蛋白序列表征—多源生物学特征」两模态。凡在别处见到同名缩写，须注意与本框架区分。

全部实验代码以 MIT 许可证公开于 GitHub 仓库 <https://github.com/rschen923/clef_repro>，获取方式见 1.2.1 节。

### 1.1.2　数据来源声明

本方案的**全部实验结果均基于程序化合成的确定性生成式基准（SyntheticWorld）**，不使用、不下载、也不分发任何真实生物学数据。作出这一选择的三条理由如下。

其一，**机制隔离**。合成世界可人为设定「真实效应方向」与「各模态所观测到的坐标子集」，从而把「多模态互补增益」这一待验证机制单独隔离出来测量，不受真实数据中同源泄漏、标注噪声、模态缺失等混杂因素的干扰。其二，**可复现性**。全部数据由固定随机种子生成，任何人在任何机器上重新运行都会得到逐位一致的数据，无需下载数吉字节的外部文件，也不受数据库版本更新的影响。其三，**成本**。真实效应蛋白标注的获取成本极高，且须经同源去冗余与严格的划分协议才能使用，超出课程作业的范围。

需要明确记录的是：`data.py` 中的 `load_real_esm_embeddings` 是一个**接口桩函数**，在未提供本地 `.npz` 文件时**显式报错并提示**，不会静默伪造数据。报告中引用的公开资源（UniProt/Swiss-Prot、GO、PDB、ESM-2、Foldseek、BioBERT、DeepSecE、CD-HIT）在本方案中**仅作为方法学设计参照与预期迁移来源**，其数据与权重未被本方案获取或再分发；完整出处与致谢见第十章 10.7 节。

### 1.1.3　所服务的研究问题

在上述前提下，本方案的全部代码只服务于一个被形式化的研究问题：

> 在标注预算固定且稀缺的条件下，以跨模态对比预训练所得的表征，相对于冻结的通用序列表征，能在下游效应蛋白二分类任务上带来多少性能增益；该增益等效于替代了多少条标注；该效应的适用边界位于何处。

为使该问题可被因果地回答，方案将其拆解为三条可执行的工作线。三条工作线分别对应"机制是否成立""增益如何随资源变化""结论在何种缺陷条件下仍成立"三类问题。

| 工作线    | 对应实验      | 所回答的问题                  | 关键量              |
| :----- | :-------- | :---------------------- | :--------------- |
| 主效应    | A、C、D     | 机制是否有效                  | MCC、标注替代率 Δ_ASR  |
| 预算与效率  | B、E、F、G、H | 增益随预算、池规模、超参数如何变化       | 性能—预算曲线、幂律指数     |
| 稳健与必要性 | I、J、K     | 噪声条件下是否稳健、哪些模态必要、结果是否显著 | 差距侵蚀率、留一曲线、$p$ 值 |

该拆解的依据是：一个方法学主张若要成立，必须同时给出效应存在性（实验 A）、效应随关键资源的响应曲线（实验 B、E、F）、超参数敏感性（实验 G、H）、在真实场景常见缺陷下的稳健性（实验 I、J），以及统计显著性（实验 K）。缺少其中任何一项，主张的适用范围都无法被界定。

### 1.2.2　三条执行路径

本方案提供三条使用路径，分别面向首次复现、分步调试与敏感性探索。

**路径一：一键全量复现。** 该路径依次运行全部十一组实验与全部绘图脚本，适用于首次使用。


```bash

```

## 1.4　术语约定

本方案涉及若干专业术语。为避免歧义，此处给出核心术语的首次定义；其余术语在正文首次出现处随文解释。

**模态（modality）。** 指描述同一对象的、信息内容与来源相互独立的若干种数据表示之一。本方案中，一个蛋白质的模态包括其氨基酸序列、进化统计、三维结构、功能注释与实验证据。

**表征（representation）。** 指由模型学习得到的、对原始数据的高层抽象向量。与人工设计的"特征"（feature）相对，表征由数据驱动自动习得。

**对比学习（contrastive learning）。** 指一类无监督表征学习方法。其做法为构造正样本对（应相互接近）与负样本对（应相互远离），训练模型使正样本对在表示空间中靠近、负样本对远离。

**冻结（freeze）。** 指将模型的某部分参数固定，使其不参与梯度更新。本方案中 Baseline 臂的投影矩阵被冻结，用以模拟"未经任务适配的通用表征"。

**三臂对照（three-arm comparison）。** 指包含下界臂、处理臂与上界臂的对照实验设计。本方案中三臂分别为 Baseline、CLEF 与 Ceiling。

**标注替代率（annotation substitution rate，Δ_ASR）。** 指跨模态预训练所带来的性能增益，相对于充足标注所能带来的性能增益的比值。该指标将性能增益换算为标注量单位。

# 第二章　环境搭建与目录结构

## 2.1　硬件与操作系统要求

本方案的全部实验均设计为在中央处理器（central processing unit，CPU）上运行，不需要图形处理器（graphics processing unit，GPU）。该设计选择的依据有二：其一，合成基准的数据规模与模型规模都很小（模型参数量为十万量级，数据集为数千条），CPU 足以在可接受的时间内完成；其二，不含 GPU 依赖可使实验的可复现性与可及性大幅提升，任何一台普通个人计算机均可完整复现全部结果。

实测运行环境为：Python 3.12，torch 2.14.1（CPU 版），numpy 2.5.4，matplotlib 3.11.2，scikit-learn 1.9.1，pandas 3.0.6。上述版本为实测通过的最低参照，更高的版本通常亦可运行。

操作系统方面，Linux、macOS 与 Windows 均可。唯一与操作系统相关的注意事项为中文字体配置（见 2.5 节）。

## 2.2　Python 环境与虚拟环境

推荐在独立的虚拟环境中安装依赖，以避免与系统级 Python 包发生冲突。创建与激活虚拟环境的命令如下。

```bash
# 创建虚拟环境（目录名任意，此处取 .venv）
python -m venv .venv

# 激活（Linux / macOS）
source .venv/bin/activate

# 激活（Windows，Git Bash）
source .venv/Scripts/activate

# 激活（Windows，cmd）
.venv\Scripts\activate.bat
```

虚拟环境的作用为：将本项目的依赖与系统环境隔离，从而在实验结束后可整体删除而不影响其他项目。若在共享服务器上运行，虚拟环境还可避免因依赖版本冲突而影响其他用户。

## 2.9　随机性控制机制

本方案涉及三类相互独立的随机性，分别由三个种子控制。理解该三分结构是理解全部对照实验设计的前提。

| 种子参数 | 控制对象 | 默认值 |
| :-- | :-- | :-- |
| `world_seed` | 合成世界的构建（正交方向、投影矩阵） | 0 |
| `data_seed` | 各数据划分的采样 | 1234 |
| `seed` | 协议随机性（模型初始化、批顺序、训练顺序） | 7 |

三者的独立性带来一项关键能力：若固定 `world_seed` 与 `data_seed` 而改变 `seed`，则得到"数据固定、协议变化"的对照；若固定 `world_seed` 与 `seed` 而改变 `data_seed`，则得到"协议固定、数据划分变化"的对照。实验 K 的十种子设计即同时扰动这三类随机性，从而给出最保守的显著性估计。

此外，训练层还提供 `set_seed` 函数，统一设置 numpy、torch 与 Python 标准库 `random` 的种子。该函数的必要性在于：若只设置 torch 的种子而不设置 numpy 的种子，则数据生成（使用 numpy）与模型训练（使用 torch）之间仍存在未受控的随机性来源，从而破坏可复现性。

# 第三章　数据层：SyntheticWorld 的构造与全部旋钮

## 3.1　采用合成基准的动机

真实生物数据上做因果推断存在三重困境。其一，不存在反事实：无法观测"若标注量不同，性能会如何变化"，因为真实数据的不同标注量并不共享同一评测集与同一类别分布。其二，无法控制变量：更换数据集会同时改变序列长度分布、家族构成与类别比例，任何性能差异都无法单独归因于所研究的变量。其三，标注稀缺本身使统计不稳定：真实效应蛋白的金标准标注量级为千级，小样本下的性能估计方差很大。

合成基准（synthetic benchmark）的作用是提供一个变量完全可控的检验场。其做法为：令全部样本共享同一个潜变量世界（latent-variable world，指由一组可解释的潜在因子生成观测数据的数据生成模型），因此世界层面的一切性质——信号结构、模态互补性、噪声强度——都可被固定，只有研究者希望考察的变量在变。该设计使因果归因成为可能，代价是外部效度的降低（见第十章）。

## 3.2　模态规格

五个生物模态被刻意设计为维度异构、噪声异构。该设计模拟真实生物学数据的异质性，同时使"逐模态归一化"这一工程措施具备存在必要。模态规格定义于 `data.py` 的 `MODALITY_SPECS`。

| 模态 | 键名 | 维度 | 噪声 $\eta_m$ | 生物学含义 | 信噪比定位 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 进化 | DP | 20 | 1.0 | DPC-PSSM（二肽组成与位置特异打分矩阵） | 最高（最干净） |
| 比对 | MSA | 128 | 1.2 | 多序列比对统计量 | 高 |
| 结构 | 3Di | 64 | 1.5 | Foldseek 结构字母表 | 中 |
| 文本 | AT | 768 | 8.0 | 基因本体注释经 BioBERT 编码 | 最低（最脏） |
| 实验 | SE | 32 | 1.3 | DeepSecE 模型输出 | 高 |

上表涉及若干专业术语，其含义如下。**DPC-PSSM**（dipeptide composition and position-specific scoring matrix）指二肽组成与位置特异打分矩阵的拼接特征，二者均由多序列比对（multiple sequence alignment，MSA，指将同源序列逐位对齐所得的矩阵）计算而来。**Foldseek 结构字母表**指将蛋白质三维结构离散化为字母序列的编码方案，其作用是把连续的三维几何转化为可被序列模型处理的符号串。**BioBERT** 指在生物医学文献上继续预训练的 BERT 语言模型，其输出为定长文本嵌入。**DeepSecE** 指一个专门用于分泌系统效应蛋白预测的既有模型，其输出被本方案用作一个模态。

关于 AT 模态为何取 768 维且噪声为 8.0：现实中的注释文本嵌入本身就是高维、高噪且信息密度低的——768 维中真正与"是否效应蛋白"相关的维度很少。该设定直接导致后续结论：AT 的净贡献接近于零。

模态拼接顺序由 `MODALITY_ORDER = ("DP", "MSA", "3Di", "AT", "SE")` 定义。该顺序在全部实验中必须保持一致，否则模态掩码（modality mask，指指示某模态是否参与拼接的布尔标记）会发生错位，从而使结果不可解释。

## 3.3　潜变量世界的生成过程

世界由若干量共同定义，且只构建一次。无标注池、训练集、验证集、测试集与上界集全部从同一世界采样。构建接口如下。

```python
SyntheticWorld(
    sigma_seq=13.5,      # 序列视角噪声（校准后值）
    eff_shift=6.4,       # 效应蛋白整体偏移幅度（校准后值）
    fam_shift=3.5,       # 家族偏移幅度（校准后值）
    signal_scale=8.0,    # 投影矩阵整体尺度（信噪比校准）
    d_z=64,              # 潜变量维度
    tok_dim=32,          # 序列每个位置的 token 维度
    seq_len=16,          # 序列长度
    n_families=5,        # 家族数 K
    mod_mask_frac=0.3,   # 每个模态随机观测的潜变量坐标比例
    mod_noise_scale=1.0, # 模态噪声整体缩放（实验 D 使用）
)
```

生成过程可分为六个步骤。以下逐步展开。

### 3.3.1　步骤一：构造正交方向

在 $d_z=64$ 维空间中采样两组方向。第一组为效应蛋白方向 $e$（一个向量），第二组为家族方向 $\{u_k\}_{k=1}^{K}$（$K=5$ 个向量）。两组方向通过 QR 分解（一种将矩阵分解为正交矩阵与上三角矩阵之积的数值方法）作正交化，得到单位向量，且 $e$ 与全部 $u_k$ 相互正交。

正交化的几何意义在于：效应与否的信息（沿 $e$ 方向）与家族归属的信息（沿 $u_k$ 张成的子空间）在信息论上相互独立。该独立性使后续分析能够干净地提问"模型学到的是效应判别能力，还是仅仅在区分家族"，而不至于让两种信息纠缠在一起。若 $e$ 与 $u_k$ 不正交，则一个"只学会区分家族"的模型也可能在效应判别指标上取得虚高的分数。

### 3.3.2　步骤二：采样潜变量

对第 $i$ 个样本，其潜变量由下式给出。

$$z_i = e\cdot e_{\text{shift}}\cdot c_i + \sum_{k=1}^{K}u_k\cdot f_{\text{shift}}\cdot w_{i,k} + N(0,I)$$

式中各项的含义如下。$c_i\in\{-1,+1\}$ 为效应蛋白二分类标签。$w_{i,k}$ 为家族权重，取独热（one-hot）或软分配形式。$e_{\text{shift}}=6.4$ 与 $f_{\text{shift}}=3.5$ 为偏移幅度，其作用是将"效应与否"与"家族归属"的信号放大到噪底之上，否则模型无法学到任何结构。最后一项 $N(0,I)$ 为每个样本的私有噪声，其存在意味着单个样本不可能被完美分类，即存在不可消除的贝叶斯错误率（Bayes error rate，指任何分类器在该数据分布上所能达到的最小错误率）。

### 3.3.3　步骤三：生成序列视角

序列视角由潜变量经线性投影并叠加噪声得到。

$$x_{\text{seq}} = A z + \sigma_{\text{seq}}\varepsilon,\qquad \varepsilon\sim N(0,I)$$

式中 $A$ 为形状 $(seq\_len\times tok\_dim)\times d_z$ 即 $512\times 64$ 的投影矩阵，其元素按 `signal_scale` 缩放；$\sigma_{\text{seq}}=13.5$ 为序列视角的噪声强度。该噪声远大于模态视角的噪声（介于 1.0 与 8.0 之间），这是一个刻意的设计：序列是"最普遍可得但最不精确"的模态，模态是"稀有但精确"的模态。CLEF 的任务正是从精确模态中学习知识，再迁移到不精确的序列上。生成后，$x_{\text{seq}}$ 被重塑为 $(seq\_len, tok\_dim)$ 的三维张量。

### 3.3.4　步骤四：生成五个模态视角

每个模态视角由潜变量经各自的投影矩阵并叠加各自的噪声得到。

$$x_m = P_m z + \eta_m\varepsilon,\qquad m\in\{\text{DP, MSA, 3Di, AT, SE}\}$$

式中 $P_m$ 为形状 $d_m\times d_z$ 的投影矩阵，$d_m$ 为该模态的维度（见 3.2 节的规格表），$\eta_m$ 为该模态的噪声强度。

### 3.3.5　步骤五：模态互补性的构造

这是全套实验中最关键的一个设计，实现于 `__post_init__` 方法中。

```python
keep = rng.random(d_z) < mod_mask_frac   # 每个模态只保留 30% 的潜变量坐标
pm[:, ~keep] = 0.0                       # 其余坐标的投影置零
```

该代码的含义为：每个模态只能"看见"潜变量 $z$ 的一部分坐标（比例由 `mod_mask_frac` 控制，默认 0.3），且不同模态看见的坐标子集不同。

该设计的必要性如下。若所有模态都能看见全部 $z$，则任意单个模态就已经包含全部信息，多模态融合将毫无收益，CLEF 所主张的"多模态红利"也就无从谈起。通过随机掩蔽，单模态的信息变为不完备（仅观测 30% 坐标），而五模态拼接可覆盖近乎全部坐标（覆盖率 $1-0.7^{5}\approx 83\%$）。于是"融合增益"在生成过程的设计层面就被保证为真实的、可测量的效应，而非噪声中的偶然波动。

据此，`mod_mask_frac` 构成多模态红利强度的总开关。将其调小（例如 0.15）会使单模态更弱、融合增益更明显；将其调大（例如 0.6）会使单模态已经足够强、融合增益趋于消失。因此该参数是做敏感性分析时应首先调整的旋钮。

须注意一处文档与代码的差异：README 中记录的 `mod_mask_frac` 为 0.5，而 `run_experiment.py` 的命令行默认值为 0.3（报告正文采用的实际值）。两者均可运行，但结果不同。进行结果比较时须确认双方使用的是同一取值。

### 3.3.6　步骤六：生成类别标签

类别标签 $y$ 的采样规则为：以概率 `p_non_effector`（默认 0.5）取 0（非效应蛋白），否则从 $1$ 至 $K$ 中均匀取一个家族编号。二分类标签由 $y_{\text{bin}}=\mathbb{1}[y>0]$ 得到。细粒度类别标签 $y_{\text{class}}$ 用于表征诊断指标的计算（见 6.2 节）。

## 3.4　模态互补性的信息论刻画

模态之间的关系可用互信息（mutual information，指两个随机变量之间共享的信息量）加以刻画。设有两个模态的表示 $X_1$ 与 $X_2$，其冗余度可定义为条件互信息与边缘互信息之比，其互补度可定义为在给定 $X_1$ 的条件下 $X_2$ 关于任务标签 $Y$ 所提供的额外信息。

在本方案的合成世界中，冗余与互补由构造显式控制：每个模态仅观测 $z$ 的 30% 坐标，且各模态观测的坐标集合不同。因此，若两个模态观测的坐标集合重叠较大，则二者冗余；若重叠较小，则二者互补。该构造使冗余与互补成为生成过程的显式参数，从而使"互补性是否带来增益"这一问题可在受控条件下被检验。实验 J 的留一法结果（留一组合普遍优于对应的单模态）即为互补性存在性的直接证据。

## 3.5　逐模态 L2 归一化

函数 `concat_modalities()` 在拼接前对每个模态单独做 L2 归一化（L2 norm，指向量各元素平方和的开方，用于将向量缩放到单位长度）。

```python
for m in MODALITY_ORDER:
    xm = xm / (np.linalg.norm(xm, axis=1, keepdims=True) + 1e-8)
X = np.concatenate([...], axis=1)
```

该步骤的必要性如下。若不归一化，则 768 维的 AT 在拼接后的向量中会天然占据

$$\frac{768}{20+128+64+768+32}=\frac{768}{1012}\approx 75.9\%$$

的能量份额（在欧氏距离的意义上，维度越高则贡献越大）。这样即使 AT 是最脏的模态（噪声 8.0），它也会在距离计算中压倒干净的 20 维 DP。归一化后，每个模态在单位球面上等权，从而由信息质量（而非维度大小）决定其贡献。这是一个纯粹为模态公平性服务的工程决定。

代码中的 `1e-8` 为数值保护项，用于避免除以零。当某样本的模态向量范数恰为零时，该保护项使其不至于产生 `inf` 或 `nan`。

## 3.6　难度旋钮的校准

难度参数的校准是本方案最容易被误读的一点，须明确说明。名义参数与实测校准值的对比如下表。

| 旋钮 | 报告名义值 | 实测校准值 | 说明 |
| :-- | :-- | :-- | :-- |
| `sigma_seq` | 6.0 | 13.5 | 名义值下序列信号被完全淹没（准确率约 0.5，不可学） |
| `eff_shift` | 1.2 | 6.4 | 校准后使 Baseline 准确率约为 0.84 |
| `fam_shift` | 0.9 | 3.5 | 校准后使 Ceiling 准确率约为 0.92 |
| `signal_scale` | 未指定 | 8.0 | 投影矩阵整体尺度 |
| `d_z` | 未指定 | 64 | 潜变量维度 |

名义参数组合失效的原因在于：$e_{\text{shift}}=1.2$ 相对于 $\sigma_{\text{seq}}=6.0$ 过小，导致效应蛋白与非效应蛋白的分布在潜空间中完全重叠，任何分类器都只能达到随机水平（准确率约 0.5）。该情形并非代码缺陷，而是名义参数未经可行性检验。

校准的正确理解为：调节旋钮直至合成基准的难度落在报告所给的经验区间内（Baseline 约 0.84，Ceiling 约 0.92），从而使后续对比与报告口径一致。换言之，校准的目的是对齐难度，而非对齐参数。

该校准的局限必须明确说明：13.5 这一数值只在当前参数化下具备语义，不能映射到真实数据的噪声水平。因此，基于该校准的结论（尤其是实验 D 的噪声鲁棒性结论）应表述为"在当前合成设定下"。

全部旋钮均可通过命令行覆盖，因此可以进行诸如"若噪声为 20 会怎样"这类探索。


# 第四章　模型层：双编码器、InfoNCE 与 VIB

## 4.1　模型类的职责

`model.py` 定义了全部网络模块。各模块的职责与参数量如下表。

| 类 | 作用 | 参数量 |
| :-- | :-- | :-- |
| `FrozenSeqBaseline` | 冻结的随机投影序列表征（Baseline 与 Ceiling 臂使用） | 0（投影矩阵注册为缓冲，不参与训练） |
| `EncoderA` | 序列表征通路（Transformer 编码器） | 约 10 万 |
| `EncoderB` | 模态表征通路（浅层 MLP） | 约 0.9 万 |
| `DownstreamClassifier` | 下游二分类头 | 10 561 |
| `VIBEncoder` | 变分信息瓶颈包装（实验 C 使用） | 复用 `EncoderA` 输出，另加两个线性层 |

表中的 **MLP**（multi-layer perceptron，多层感知机）指由若干全连接层堆叠而成的前馈网络；**Transformer** 指以自注意力（self-attention）为核心机制的序列建模架构；**缓冲（buffer）** 指注册在模块中但不参与梯度更新的张量。

## 4.2　FrozenSeqBaseline：基线为何必须如此"弱"

```python
class FrozenSeqBaseline(nn.Module):
    def __init__(self, tok_dim, out_dim=128, seed=0):
        g = torch.Generator().manual_seed(seed)
        w = torch.randn(tok_dim, out_dim, generator=g) / math.sqrt(tok_dim)
        self.register_buffer("W", w)     # 冻结的随机投影矩阵
    def forward(self, x):
        return x.mean(dim=1) @ self.W    # 平均池化 + 线性投影
```

该类代表"不做任何跨模态预训练，直接使用通用序列表征"的情形。其设计包含三个关键特征。

其一，投影矩阵在随机初始化后被冻结。`register_buffer` 的含义是该张量会被保存进模型的 `state_dict`（模型参数的字典表示）并随模型移动设备，但不参与梯度更新，也不会被优化器看到。这模拟了"使用一个未经本任务适配的通用表征"。

其二，仅做平均池化。`x.mean(dim=1)` 将形状 $(16, 32)$ 的序列沿位置维取平均，压成 32 维，再经线性投影映射到 128 维。这是最简单的序列表征提取方式。

其三，可训练参数量为零。因此 Baseline 臂唯一被训练的是下游分类头（10 561 个参数）。

该设计之所以公平，理由如下。CLEF 臂的核心主张是"预训练带来的增益"。若基线本身就是一个强模型（例如可学习的 Transformer），则 CLEF 的增益会同时包含"预训练"与"更强的架构"两个因素，从而无法归因。以冻结的随机投影作为基线，就把架构能力这一变量彻底固定，只留下"预训练"这一个差异，这正是因果归因所要求的。

该选择的代价是：基线可能"弱到不真实"。真实场景下，研究者至少会使用 ESM-2 等现成模型的表征。因此报告的结论应表述为"相对于一个未经适配的通用序列表征"，而非"相对于全部已有方法"。该限制的完整讨论见讲解报告第十章局限七。


## 4.3　EncoderA：序列通路

```python
EncoderA(seq_len=16, tok_dim=32, d_model=48, n_heads=4, n_layers=2, out_dim=128)
# 前向：输入 -> 位置编码 -> 两层编码器 -> 平均池化 -> 投影 MLP -> 128 维
```

逐层解析如下。

| 层 | 形状变化 | 作用 |
| :-- | :-- | :-- |
| `inp`（线性层） | $(B,16,32)\to(B,16,48)$ | 将 token 映射到模型维度 |
| `pos`（位置编码） | $(B,16,48)$ | 叠加位置编码（序列顺序具有意义） |
| `encoder` | $(B,16,48)\to(B,16,48)$ | 两层 Transformer 编码器，4 头自注意力 |
| `pool` | $(B,16,48)\to(B,48)$ | 沿序列维平均池化 |
| `proj`（MLP） | $(B,48)\to(B,128)$ | 投影到跨模态对比空间 |

其中 **token** 指序列中的一个基本单元（此处为蛋白质序列的一个位置）；**位置编码（positional encoding）** 指向输入叠加的、用于标识各位置次序的可学习向量；**自注意力头数（n_heads）** 指将注意力计算拆分为若干并行子空间的数目。

此处涉及一项与 CLEF 直接相关的技术细节：InfoNCE 损失涉及批次内全部样本的两两相似度，因此其梯度不仅经由正样本对回传，也经由全部负样本对回传。这意味着批次大小 $B$ 不仅是计算效率的考量，也直接影响梯度所包含的信息量。$B$ 越大，每个正样本面对的负样本越多，梯度中对"区分性"的要求越强。该机制正是实验 F 中池规模下限现象的根源。

选择 Transformer 而非循环神经网络（recurrent neural network，RNN）或卷积神经网络（convolutional neural network，CNN）的依据是：序列长度仅为 16，Transformer 的全局注意力在此规模下没有计算负担，且能一次性建模全部位置之间的关系。4 头、2 层是刻意的小规模配置，目的是不让编码器容量成为性能来源，从而保证增益归因于对比预训练而非更大模型。

## 4.4　EncoderB：模态通路

```python
EncoderB(in_dim=1012, hidden=64, out_dim=128)
# Linear(1012,64) -> GELU -> Linear(64,128)
```

输入维度等于归一化后五模态拼接的总维度，即 $20+128+64+768+32=1012$。

采用浅层 MLP 的依据有二。其一为忠实性：模态特征（DP、MSA、3Di、AT、SE）是已经处理好的特征向量，不像原始序列那样需要复杂建模，因此浅 MLP 与这一事实相匹配。其二为因果干净：若 `EncoderB` 很深，则"多模态表征更好"可能只是因为模态通路本身更强，而非对比学习令两个通路对齐；浅 MLP 可排除该混淆。

参数量方面，`EncoderB`（约 0.9 万）远小于 `EncoderA`（约 10 万）。该不对称是合理的：`EncoderA` 需要处理原始序列（更难），`EncoderB` 只处理特征（更易）。

## 4.5　对称 InfoNCE

```python
def symmetric_infonce(z, z_prime, tau=0.5):
    z = F.normalize(z, dim=-1)
    z_prime = F.normalize(z_prime, dim=-1)
    logits = z @ z_prime.t() / tau            # (B, B)
    labels = torch.arange(B, device=z.device)
    loss_ab = F.cross_entropy(logits, labels)       # A 找 B
    loss_ba = F.cross_entropy(logits.t(), labels)   # B 找 A
    return 0.5 * (loss_ab + loss_ba)
```

**InfoNCE**（Info Noise Contrastive Estimation，信息噪声对比估计）是对比学习的核心损失函数。逐步理解其实现如下。

第一步为归一化。将两个表征都投影到单位球面上。该步骤很关键：它使点积变为余弦相似度（cosine similarity，指两向量夹角的余弦，与向量长度无关），从而自动消除模态间的尺度差异。若不归一化，则 768 维向量的点积天然大于 20 维向量，会主导 softmax。

第二步为相似度矩阵。`logits[i,j]` 表示第 $i$ 个序列样本与第 $j$ 个模态样本的相似度除以温度 $\tau$，构成一张 $B\times B$ 的表。

第三步为对角正样本。第 $i$ 个序列样本的正确配对是第 $i$ 个模态样本（二者来自同一蛋白），因此训练目标是将对角元素推高、将非对角元素（批内其他样本，即负样本）压低。

第四步为双向平均。$A\to B$（序列寻找模态）与 $B\to A$（模态寻找序列）两个方向各计算一次交叉熵（cross entropy，一种度量两个概率分布差异的损失函数）再取平均。必须双向的理由是：对比学习的目标是"两侧互相能够识别对方"，单向会引入不对称性，使其中一侧退化为"只提供线索、不学习结构"。

温度 $\tau=0.5$ 的作用为控制 softmax 的尖锐程度。$\tau$ 越小，分布越尖，模型被迫将正确配对与最相似的错误配对区分开，学习更激进但容易不稳；$\tau$ 越大，分布越平，学习更平滑但区分力较弱。实验 G 专门扫描了该参数。

批内负样本的含义为：当 $B=256$ 时，每个正样本面对 255 个负样本。这些负样本来自同一批次内其他蛋白的模态特征，它们与当前样本的差异提供了"什么是不同"的对比信息。这正是池规模不能太小的原因（实验 F）：池太小则批内负样本高度相似，对比信号退化。

## 4.6　DownstreamClassifier：下游分类头

```python
class DownstreamClassifier(nn.Module):
    def __init__(self, in_dim=128, hidden=80):
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.LayerNorm(hidden),
            nn.ReLU(),
            nn.Linear(hidden, 1),
        )
    def forward(self, x):
        return self.net(x).squeeze(-1)   # (B,) logits
```

该分类头为两层 MLP 加层归一化（layer normalization，指对单样本的激活值作归一化，以稳定训练）加 ReLU 激活。隐藏层维度取 80，使参数量约为 1.05 万，与报告口径一致。全部实验臂共用同一结构、同一参数量，以保证"除表征来源与标注预算外其余完全一致"。

输出为 logit（未经过 sigmoid 的实数分数），与 `BCEWithLogitsLoss` 配套使用。**BCE**（binary cross entropy，二值交叉熵）为二分类任务的常用损失函数。直接使用带 logits 的版本而非先做 sigmoid 再算交叉熵，是出于数值稳定性考虑：该实现在内部使用 log-sum-exp 技巧，避免概率接近 0 或 1 时出现溢出。

## 4.7　VIBEncoder：变分信息瓶颈

```python
class VIBEncoder(nn.Module):
    def forward(self, h):
        mu = self.mu_layer(h)
        logvar = self.logvar_layer(h).clamp(-8.0, 8.0)   # 数值稳定
        std = torch.exp(0.5 * logvar)
        eps = torch.randn_like(std)
        z = mu + eps * std                                # 重参数化
        return z, mu, logvar

def kl_divergence(mu, logvar):
    return -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp(), dim=1).mean()
```

**信息瓶颈（information bottleneck）** 的核心思想为：优良的表征应在保留与任务相关信息的同时，压缩与任务无关的信息。标准的对比学习只要求"表征保留足够信息以对齐模态"，却不限制保留多少。**变分信息瓶颈（variational information bottleneck，VIB）** 额外施加一个约束——表征应向标准正态分布 $N(0,I)$ 靠近，即"能少保留就少保留"。

完整目标函数为

$$\mathcal{L}=\mathcal{L}_{\text{InfoNCE}}+\beta\cdot\operatorname{KL}\big(q(z|x)\,\|\,N(0,I)\big),$$

$$\operatorname{KL}=-\frac{1}{2}\sum_k\big(1+\log\sigma_k^{2}-\mu_k^{2}-\sigma_k^{2}\big).$$

式中 **KL 散度**（Kullback–Leibler divergence）为度量两个概率分布差异的量。$\beta$ 的作用是权衡"对齐任务"与"压缩任务"：$\beta=0$ 时退化为普通 InfoNCE；$\beta$ 越大，表征越被压向原点附近的球形分布。

**重参数化技巧（reparameterization trick）** 的必要性在于：$z=\mu+\sigma\odot\varepsilon$ 将随机性从参数中"外移"到 $\varepsilon$，从而令梯度可以穿过采样操作（$z$ 对 $\mu$ 与 $\sigma$ 可导）。这是变分自编码器（variational autoencoder，VAE）的标准技巧。

`clamp(-8.0, 8.0)` 的作用为防止 $\log\sigma^{2}$ 发散导致 `exp` 溢出。由于 InfoNCE 本身不约束 $\sigma$，若不加 clamp，训练后期 $\sigma$ 可能爆炸。

报告之所以要求"暴露终态 KL 项"，是因为 KL 的大小反映了表征被压缩的程度。报告发现 $\beta$ 增大时终态 KL 并非单调变化，这提示 InfoNCE 与 KL 两个目标之间存在张力：InfoNCE 希望将表征撑开（需要较大方差以区分样本），KL 希望将其压紧。终态 KL 是这两股力量博弈的结果，而非简单随 $\beta$ 单调上升。该现象是实验 C 最主要的发现。

## 4.9　build_clef 工厂函数

```python
def build_clef(tok_dim, seq_len, modality_in_dim, *, d_model=48, n_heads=4,
               n_layers=2, out_dim=128, encoder_b_hidden=64, use_vib=False):
    encoder_a = EncoderA(tok_dim, seq_len, d_model, n_heads, n_layers, out_dim)
    encoder_b = EncoderB(modality_in_dim, hidden=encoder_b_hidden, out_dim=out_dim)
    vib = VIBEncoder(out_dim, out_dim) if use_vib else None
    return {"encoder_a": encoder_a, "encoder_b": encoder_b, "vib": vib}
```

该工厂函数集中构建一套 CLEF 编码器，返回包含两个编码器与可选 VIB 的字典。其作用为统一超参数的默认值，使编排层无需重复书写。当 `use_vib=False` 时，返回的 `vib` 为 `None`，训练循环据此走普通 InfoNCE 分支。

## 5.1　随机性控制

```python
def set_seed(seed):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
```

该函数统一设置 Python 标准库、numpy 与 torch 的随机种子。其必要性在于：数据生成使用 numpy，模型训练使用 torch，若只设置其中之一，则仍存在未受控的随机性来源，从而破坏可复现性。`torch.cuda.manual_seed_all` 在 CPU 环境下无实际作用，保留它是为了代码在 GPU 环境下同样正确。

须注意一处实现细节：`_clef_rep` 在创建编码器之前显式调用 `set_seed(seed)`。这是为了令权重初始化可复现，而不依赖于调用之前的全局随机状态。若省略该调用，则两次运行可能因前置操作的随机数消耗不同而得到不同的初始化，从而破坏可复现性。

## 5.2　阶段一：对比预训练

```python
def pretrain_contrastive(x_seq, x_mod, encoder_a, encoder_b, *, vib=None, beta=0.0,
                         epochs=50, batch_size=256, lr=1e-3, tau=0.5, seed=42,
                         device="cpu", verbose=False):
    set_seed(seed)
    params = list(encoder_a.parameters()) + list(encoder_b.parameters())
    if vib is not None:
        params += list(vib.parameters())
    optimizer = torch.optim.Adam(params, lr=lr)
    for epoch in range(epochs):
        perm = torch.randperm(n)
        for start in range(0, n, batch_size):
            idx = perm[start:start+batch_size]
            h_a = encoder_a(seq_t[idx])
            h_b = encoder_b(mod_t[idx])
            if vib is not None:
                z_a, mu, logvar = vib(h_a)
                kl = kl_divergence(mu, logvar)
                loss, _, _ = symmetric_infonce(z_a, h_b, tau=tau)
                loss = loss + beta * kl
            else:
                loss, _, _ = symmetric_infonce(h_a, h_b, tau=tau)
            optimizer.zero_grad(); loss.backward(); optimizer.step()
    return {"curve": curve, "final_loss": ..., "final_kl": final_kl, ...}
```

**Adam**（adaptive moment estimation，自适应矩估计）为一种对每个参数自适应调整有效学习率的优化器：对梯度长期较小的参数使用较大步长，对梯度长期较大的参数使用较小步长。该自适应性使 Adam 对学习率的初始选择相对不敏感。

关键细节归纳如下表。

| 细节 | 取值 | 依据 |
| :-- | :-- | :-- |
| 数据来源 | 无标注池（4000 条，无标签） | 对比预训练为无监督，不需要标签 |
| 批大小 | 256 | 决定批内负样本数（255 个） |
| 优化器 | Adam | 对稀疏梯度与不同尺度参数适应良好 |
| 学习率 | $10^{-3}$ | 对比学习的常用起点 |
| 轮数 | 50（实验 A）／30（实验 B–D） | 50 用于主实验，30 用于节省扫描时间 |
| 验证集 | 不使用 | 对比学习为无监督，无天然的早停判据 |
| 冻结层 | 无 | `EncoderA` 与 `EncoderB` 全部参与训练 |

关于预训练轮数取 50 而扫描取 30 的权衡：主实验（A）需要充分收敛以给出可信的 Δ_ASR；而实验 B–D 与 E–K 需要多组重复（多种子、多档参数），若均用 50 轮会显著拖长总时间，30 轮足以使趋势稳定。这意味着跨实验比较绝对值时须注意该差异，但实验内部的对照（同一轮内的比较）是公平的。

**批大小的两难。** 批大小 $B$ 的选取存在权衡。$B$ 越大，梯度方差越小（因为是更多样本的平均），训练越稳定，且批内负样本越多；但 $B$ 越大，每轮迭代所需内存越多，且可能降低泛化（因梯度噪声减少，可能落入尖锐极小值）。本方案在预训练阶段取 $B=256$，在下游阶段取 $B=64$。下游阶段取较小批大小的原因是：标注样本总数仅为 100 条，若批大小超过样本数，则一轮仅含一次参数更新，无法充分优化分类头。

预训练结束时保存的曲线记录于 `results/curves.json`，记录每轮的平均 InfoNCE 值，是诊断"训练是否收敛"的第一手材料。健康的曲线应表现为：前几轮快速下降，之后平缓下降，无剧烈震荡。

## 5.3　阶段二：下游有监督分类

```python
def train_downstream(rep_train, y_train, rep_val, y_val, *, hidden=80, epochs=300,
                     batch_size=64, lr=1e-3, weight_decay=1e-4, patience=30, seed=42):
    # z-score 标准化：统计量只用训练集
    mu = rep_train.mean(axis=0, keepdims=True)
    sigma = rep_train.std(axis=0, keepdims=True) + 1e-6
    rep_tr = (rep_train - mu) / sigma
    rep_va = (rep_val - mu) / sigma
    clf = DownstreamClassifier(in_dim=rep_train.shape[1], hidden=hidden)
    optimizer = torch.optim.Adam(clf.parameters(), lr=lr, weight_decay=weight_decay)
    for epoch in range(epochs):
        # 训练一轮（BCE）
        val_f1 = _f1_from_logits(clf(xv), yv)
        if val_f1 > best_f1 + 1e-6:
            best_f1, best_state, bad = val_f1, deepcopy(clf.state_dict()), 0
        else:
            bad += 1
            if bad >= patience: break          # 早停
    clf.load_state_dict(best_state)
    return {"classifier": clf, "best_val_f1": best_f1, "best_epoch": best_epoch,
            "mu": mu, "sigma": sigma}
```

**z-score 标准化** 指将数据减去均值再除以标准差，使其均值为 0、标准差为 1。该步骤的作用是令不同表征来源的尺度一致，从而使分类头的初始条件可比。

四个必须注意的细节如下。

其一，标准化统计量只取自训练集。`mu` 与 `sigma` 由 `rep_train` 计算，然后原封不动地应用于验证集与测试集。若对测试集单独计算统计量，则构成数据泄漏（data leakage，指测试集信息以任何形式渗入训练过程），会使结果虚高。这是一个极其常见且致命的错误。

其二，早停判据为验证集 F1。**F1** 为精确率与召回率的调和平均。之所以用 F1 而非损失或准确率，是因为在类别不平衡条件下，损失与准确率都可能被多数类主导，而 F1 更能反映少数类的检出质量。


其三，最优状态需保存并回滚。`best_state` 在验证 F1 提升时保存，训练结束后通过 `load_state_dict` 恢复。若省略该步骤，则模型停留在最后一轮（可能已过拟合），早停反而会损害性能。

其四，`patience=30` 表示验证 F1 连续 30 轮无提升则停止。该阈值较宽松，因为下游训练本身很轻（仅约 1 万参数），单轮耗时极短。

**weight_decay**（权重衰减）为一种正则化手段，通过在损失中隐式加入参数平方惩罚来抑制过拟合。此处取 $10^{-4}$。

## 5.4　三臂的训练差异

三臂的配置对比如下表。表中除表征来源与标注量外的全部列均相同。

| 臂 | 表征来源 | 标注量 | 分类头 | 优化器与早停 | 评测集 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| Baseline | `FrozenSeqBaseline`（冻结随机投影） | 100 | 相同 | 相同 | 相同 |
| CLEF | `EncoderA`（对比预训练后） | 100 | 相同 | 相同 | 相同 |
| Ceiling | `FrozenSeqBaseline`（与 Baseline 同） | 1500 | 相同 | 相同 | 相同 |

该协议的精髓如下。Baseline 与 Ceiling 的表征完全相同（均为同一份冻结投影），唯一差别是标注量。因此 `Ceiling − Baseline` 精确地度量了"在相同表征下，额外提供 1400 条标注能带来多少提升"，该量即 Δ_ASR 的分母。而 `CLEF − Baseline` 度量了"在相同 100 条标注下，换用更好的表征能带来多少提升"。两者的比值即为"表征提升等效于多少标注"。

## 5.5　数值稳定性措施

本方案在若干位置加入了数值保护措施，汇总如下。

| 位置 | 措施 | 目的 |
| :-- | :-- | :-- |
| 模态 L2 归一化 | `+ 1e-8` | 避免除零 |
| z-score 标准化 | `+ 1e-6` | 避免标准差为零时除零 |
| VIB 的 `logvar` | `clamp(-8.0, 8.0)` | 避免 $\exp$ 溢出 |
| Δ_ASR 计算 | 分母绝对值小于 $10^{-8}$ 时返回 0 | 避免除零产生 `inf` |
| 早停比较 | `> best_f1 + 1e-6` | 避免浮点相等导致的抖动 |
| F1 计算 | 分母 `+ 1e-12` | 避免 TP 为零时除零 |

这些措施的共同作用是：令边界情形下程序不崩溃、不产生 `inf` 或 `nan`，且不因浮点误差而产生虚假的"提升"。

# 第六章　评估层：三层指标的算法实现

## 6.1　下游分类指标

```python
def classification_metrics(y_true, y_prob, thr=0.5):
    y_pred = (y_prob >= thr).astype(int)
    return {
        "ACC":   accuracy_score(y_true, y_pred),
        "REC":   recall_score(y_true, y_pred, zero_division=0),
        "PR":    precision_score(y_true, y_pred, zero_division=0),
        "F1":    f1_score(y_true, y_pred, zero_division=0),
        "MCC":   matthews_corrcoef(y_true, y_pred),
        "AUPRC": average_precision_score(y_true, y_prob),
    }
```

各指标的数学定义与适用场景如下表。表中 $TP$、$TN$、$FP$、$FN$ 分别表示真阳性、真阴性、假阳性与假阴性。

| 指标 | 数学定义 | 适用场景与陷阱 |
| :-- | :-- | :-- |
| ACC（准确率） | $(TP+TN)/N$ | 类别平衡时直观；不平衡时虚高（全预测多数类亦可得高分） |
| REC（召回率） | $TP/(TP+FN)$ | 关心漏检代价时（如病原筛查） |
| PR（精确率） | $TP/(TP+FP)$ | 关心误报代价时（如实验验证成本） |
| F1 | $2\cdot PR\cdot REC/(PR+REC)$ | 精确率与召回率的调和平均；不平衡下优于准确率 |
| MCC（马修斯相关系数） | 见下式 | 主判据：对类别不平衡稳健，四个混淆矩阵元素均参与 |
| AUPRC（PR 曲线下面积） | 积分 | 全阈值排序质量，不依赖单一阈值 |

$$\text{MCC}=\frac{TP\cdot TN-FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}$$

**马修斯相关系数（Matthews correlation coefficient，MCC）** 取值范围为 $[-1,1]$：$1$ 表示完美预测，$0$ 表示随机水平，$-1$ 表示完全反向。

以 MCC 作为主判据的依据有三。其一，它对类别不平衡稳健：设正类比例为 $p$，则全预测为正类的方法其准确率为 $p$ 而 MCC 为 0。其二，它是单一综合分数：精确率与召回率存在此消彼长的关系，单报其一均失之片面，而 F1 忽略了真阴性。其三，它与卡方统计量存在等价关系，因而具备统计可解释性，而非人为构造的分数。

为具体说明准确率的失效方式，构造一个数值例子。设测试集含 800 个样本，其中正类 200 个、负类 600 个。方法甲将全部样本预测为负类，其准确率为 $600/800=0.750$，而 MCC 为 0（因 $TP$ 与 $FP$ 均为 0，分子为零）。方法乙正确识别全部正类中的 120 个，同时误报 60 个负类，其混淆矩阵为 $TP=120$、$FN=80$、$FP=60$、$TN=540$，准确率为 $(120+540)/800=0.825$，MCC 为

$$\text{MCC}=\frac{120\times 540-60\times 80}{\sqrt{(120+60)(120+80)(540+60)(540+80)}}=\frac{64800-4800}{\sqrt{180\times 200\times 600\times 620}}\approx 0.449.$$

对比可见，方法甲的准确率（0.750）仅比方法乙（0.825）低 0.075，但在 MCC 上二者分别为 0 与 0.449，差距极大。若仅报告准确率，则一个完全没有判别能力的方法会被误认为接近一个具有实质判别能力的方法。这是本项目在分类高度不平衡场景下以 MCC 为主判据的数值依据。

AUPRC 与 MCC 的差异在于是否依赖阈值。给定分类器输出的概率分数，须经阈值化方可计算 MCC；不同阈值会产生不同的混淆矩阵，从而产生不同的 MCC。若允许为各方法分别调节最优阈值，则阈值本身即成为可调参数，从而使比较失去公平性。本方案固定所有方法使用同一阈值 0.5，正是为消除这一自由度。AUPRC 则不需要阈值：它遍历全部阈值，对每个阈值计算精确率与召回率并绘制曲线，取曲线下面积。二者互补：MCC 回答"在 0.5 阈值下判别是否准确"，AUPRC 回答"无论阈值如何，排序是否合理"。

## 6.2　表征诊断指标

```python
def representation_diagnostics(rep, y_class, seed=42, max_asw=2000):
    km = KMeans(n_clusters=n_clusters, n_init=10, random_state=seed).fit(rep)
    ari = adjusted_rand_score(y_class, km.labels_)
    nmi = normalized_mutual_info_score(y_class, km.labels_)
    if rep.shape[0] > max_asw:
        idx = rng.choice(rep.shape[0], size=max_asw, replace=False)
        asw = silhouette_score(rep[idx], y_class[idx])
    else:
        asw = silhouette_score(rep, y_class)
    return {"ARI": ari, "NMI": nmi, "ASW": asw}
```

各指标的含义与读法如下表。

| 指标 | 含义 | 读法 |
| :-- | :-- | :-- |
| ARI（调整兰德指数） | 聚类结果与真实类别划分的一致性 | 0 表示随机，1 表示完全一致；对簇数不敏感 |
| NMI（归一化互信息） | 同上，信息论版本 | 对簇数略敏感，与 ARI 互为佐证 |
| ASW（平均轮廓宽度） | 簇内紧凑与簇间分离的平均程度 | $-1$ 至 $+1$，越大越好；下采样至 2000 以控制 $O(n^{2})$ 成本 |

**调整兰德指数（adjusted Rand index，ARI）** 度量两种划分的一致性并校正随机水平；**归一化互信息（normalized mutual information，NMI）** 为互信息的归一化版本；**平均轮廓宽度（average silhouette width，ASW）** 为各样本轮廓系数的平均，其中样本 $i$ 的轮廓系数为

$$s(i)=\frac{b(i)-a(i)}{\max\{a(i),b(i)\}},$$

$a(i)$ 为样本 $i$ 与同类其他样本的平均距离，$b(i)$ 为样本 $i$ 与最近异类样本的平均距离。

这三个指标的价值在于它们构成过程性证据。其计算完全不依赖下游分类器的训练，只需对表征本身作聚类，再将聚类结果与真实划分比较。因此，表征诊断指标所衡量的是"表征是否已将数据结构组织好"这一属性，而非"分类器是否被训练好"。若下游性能提升而表征诊断指标未提升，则说明性能提升可能并非来自表征结构改善，而是来自分类头对特定噪声的过拟合；三者同时提升，才是"表征确实学好了"的强证据。

`max_asw=2000` 的必要性在于：`silhouette_score` 的计算复杂度为 $O(n^{2})$。测试集为 800 条（可直算），但若在无标注池（4000 条）或更大数据上计算会明显变慢。下采样是工程取舍，且使用固定种子以保证可复现。

## 6.3　标注替代率 Δ_ASR

```python
def annotation_substitution_rate(clef, baseline, ceiling):
    denom = ceiling - baseline
    if abs(denom) < 1e-8:
        return 0.0                     # 分母趋零时返回 0，避免 inf
    return float((clef - baseline) / denom)
```

$$\Delta_{\text{ASR}}=\frac{M_{\text{CLEF}}-M_{\text{Base}}}{M_{\text{Ceil}}-M_{\text{Base}}}$$

式中 $M$ 为任一评价指标（例如 MCC）。分子的含义为"换用更好表征所带来的提升"，分母的含义为"标注量从 100 条增加到 1500 条所带来的提升"。比值即为"表征的提升等效于多少比例的标注增加"。

其取值的解读如下。$\Delta_{\text{ASR}}=1.0$ 表示表征提升等效于额外增加 1400 条标注，即完全替代；$\Delta_{\text{ASR}}>1.0$ 表示表征提升超过 1400 条标注的效果；$\Delta_{\text{ASR}}<0$ 表示表征提升为负，即 CLEF 反而不如基线。

`1e-8` 保护的意义在于：当标注预算接近 1500 时，分母趋零，比值会发散。代码选择返回 0.0 而非 `inf` 或 `nan`，这是一个保守的处理（宁可低估，也不给出误导性的巨大数字）。该指标的适用边界在讲解报告第十章第三节中有完整分析。

## 6.4　evaluate_arm：一次评估产出三层指标

```python
def evaluate_arm(rep_test, y_test, y_class_test, y_prob):
    out = classification_metrics(y_test, y_prob)          # 第一层：下游分类
    out.update(representation_diagnostics(rep_test, y_class_test))  # 第二层：表征质量
    return out
```

编排层的 `_downstream_and_eval` 在此基础上再补充参数量（第三层：成本）。一次调用同时产出三层指标，保证所有臂使用完全相同的评测流程。这是"除被检验变量外全同"原则在代码层面的落实。

三层指标的防操纵作用如下。单层指标存在三种可操纵方式：其一为指标挑选，若仅报告准确率，则全预测多数类的方法可在正类占多数时获得较高准确率；其二为阈值挑选，若允许为各方法单独调节最优阈值，则阈值本身成为可调参数；其三为评测集挑选，若允许多次评测后选取最优结果，则该结果不代表真实性能。三层指标须同时报告且须同向，方可信。

# 第七章　主效应组实验（A–D）的逐条命令解析

主效应组由 `run_experiment.py` 驱动，包含实验 A 至实验 D 四组。该组的共同特征为：全部实验共享同一合成世界、同一数据划分与同一评测流程，每组仅操纵一个或少数几个变量。本节按实验逐条给出命令、实现路径、实测结果与解读。

在进入具体实验之前，须先明确三个贯穿全组的术语。**实验臂**（arm）指一次完整训练与评估流程，每一臂对应一个特定的"表征来源 × 标注预算"组合。**唯一变量原则**指除被检验的变量之外，各臂在分类头结构、优化器、学习率、批大小、早停准则、验证集与测试集上必须完全一致；该原则是因果归因成立的前提，若违反则观测到的差异无法被归因于被检验变量。**协议正确性检验**（protocol sanity check）指通过"预期应当不变的量是否确实不变"来反证实现无缺陷，例如基线臂只消费序列通路，则模态噪声的强度变化不应引起基线性能的任何改变。

## 7.1　实验 A：三臂对照（核心实验）

### 7.1.1　命令与目标

```bash
python run_experiment.py A
```

实验 A 是第七章三臂对照协议的首次完整实施，其目标为：在 100 条标注的固定预算下，测量跨模态对比预训练所得表征相对于冻结通用序列表征的性能增益，并将该增益换算为标注替代率 $\Delta_{\text{ASR}}$。**标注替代率**（annotation substitution rate，$\Delta_{\text{ASR}}$）指跨模态预训练所带来的净性能增益与充足标注所带来的净性能增益之比，其取值含义为"预训练替代了多少比例的标注增量缺口"。

### 7.1.2　八个实验臂的构造

实验 A 构建八个实验臂（`run_experiment.py` 中的 `ARM_SPECS` 与 `run_experiment_a`），全部在同一世界、同一划分、同一分类头下评测。

| 臂名 | 表征来源 | 模态输入 | 标注数 | 可训练参数量 |
| :-- | :-- | :-- | :-- | :-- |
| Baseline | `FrozenSeqBaseline` | 序列 | 100 | 10 561 |
| CLEF-DP | `EncoderA`（对齐 DP） | 序列 + DP | 100 | 101 905 |
| CLEF-MSA | `EncoderA`（对齐 MSA） | 序列 + MSA | 100 | 108 817 |
| CLEF-3Di | `EncoderA`（对齐 3Di） | 序列 + 3Di | 100 | 104 721 |
| CLEF-AT | `EncoderA`（对齐 AT） | 序列 + AT | 100 | 149 777 |
| CLEF-SE | `EncoderA`（对齐 SE） | 序列 + SE | 100 | 102 673 |
| CLEF-ALL | `EncoderA`（对齐五模态） | 序列 + 全部 | 100 | 165 393 |
| Ceiling | `FrozenSeqBaseline` | 序列 | 1500 | 10 561 |

表中五个单模态 CLEF 臂（DP、MSA、3Di、AT、SE）承担两项功能。其首要功能为检验"多模态融合是否优于任一单模态"；其次要功能为刻画模态增益的任务依赖结构，即不同生物模态的信息价值是否等同。**DP**（DPC-PSSM）指基于二肽组成的位置特异性打分矩阵所派生的 20 维进化特征；**MSA** 指多序列比对（multiple sequence alignment）的列统计特征；**3Di** 指 Foldseek 结构字母表所编码的结构特征；**AT** 指由 GO 注释文本经 BioBERT 编码所得的语义特征；**SE** 指由 DeepSecE 模型输出的分泌系统相关特征。

可训练参数量一列的差异须作说明。Baseline 与 Ceiling 的参数量均为 10 561，二者仅训练下游分类头，其序列表征来自冻结的随机投影矩阵，故可训练参数完全相同。各 CLEF 臂的参数量随模态维度变化：DP 模态为 20 维，故 CLEF-DP 参数量最小（101 905）；AT 模态为 768 维，故 CLEF-AT 参数量最大（149 777）；CLEF-ALL 因拼接全部五模态，参数量最大（165 393）。该列数值的比对是协议正确性检验的一部分。

### 7.1.3　实测结果

实验 A 在 `seed=7`、`data_seed=1234`、`n_train=100`、`n_ceiling=1500`、`n_pool=4000`、`pre_epochs=50`、`tau=0.5` 下运行，实测结果如下表。

| 方法 | 可训练参数 | ACC | MCC | AUPRC | ARI | NMI | ASW |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| Baseline | 10 561 | 0.8475 | 0.6950 | 0.9274 | 0.1262 | 0.1807 | 0.0119 |
| CLEF-DP | 101 905 | 0.8913 | 0.7819 | 0.9398 | 0.1828 | 0.2315 | 0.0460 |
| CLEF-MSA | 108 817 | 0.8588 | 0.7212 | 0.9262 | 0.2100 | 0.2202 | 0.0498 |
| CLEF-3Di | 104 721 | 0.8888 | 0.7774 | 0.9434 | 0.1770 | 0.2090 | 0.0329 |
| CLEF-AT | 149 777 | 0.8550 | 0.7090 | 0.9180 | 0.1299 | 0.1820 | 0.0302 |
| CLEF-SE | 102 673 | 0.8863 | 0.7722 | 0.9423 | 0.2289 | 0.2244 | 0.0558 |
| CLEF-ALL | 165 393 | **0.9075** | **0.8146** | **0.9472** | **0.2423** | **0.2831** | 0.0442 |
| Ceiling | 10 561 | 0.9113 | 0.8220 | 0.9609 | 0.1262 | 0.1807 | 0.0119 |

表中 **ACC** 为准确率（accuracy），指预测正确的样本比例；**MCC** 为马修斯相关系数（Matthews correlation coefficient），指综合考虑真阳性、真阴性、假阳性、假阴性的二分类一致性度量，取值域为 $[-1,1]$，对类别不平衡不敏感；**AUPRC** 为精确率—召回率曲线下面积（area under the precision–recall curve）；**ARI** 为调整兰德指数（adjusted Rand index），**NMI** 为标准化互信息（normalized mutual information），**ASW** 为轮廓系数（average silhouette width），三者均为表征质量诊断指标，其定义见第六章。

### 7.1.4　三项主要结论

**第一项结论：跨模态预训练显著优于纯序列基线。** 准确率由 0.8475 提升至 0.9075，相对提升 7.1%；MCC 由 0.6950 提升至 0.8146，绝对提升 0.1196；AUPRC 由 0.9274 提升至 0.9472。三项指标方向一致。此处"方向一致"具有方法论意义：单层指标可被操纵（例如仅报告准确率时，全预测多数类的方法可在正类占多数时获得较高准确率），故须三层指标同向方可信。

**第二项结论：标注替代率约为 0.94。** 其计算过程如下。

$$\Delta_{\text{ASR}}(\text{ACC})=\frac{0.9075-0.8475}{0.9113-0.8475}=\frac{0.0600}{0.0638}=0.9412,$$

$$\Delta_{\text{ASR}}(\text{MCC})=\frac{0.8146-0.6950}{0.8220-0.6950}=\frac{0.1196}{0.1270}=0.9422.$$

两项计算给出高度一致的替代率（0.9412 与 0.9422），其含义为：仅使用 $1/15$ 的标注量，跨模态预训练即将性能推进至充足标注上界的约 94%。该一致性本身是一项稳健性证据，说明结论不依赖于具体选用哪一项指标。

**第三项结论：模态增益存在明显的任务依赖结构。** 按准确率排序为


$$\text{DP}(0.8913) > \text{3Di}(0.8888) > \text{SE}(0.8863) > \text{MSA}(0.8588) > \text{AT}(0.8550).$$

该排序表明：在该合成世界中，进化信号（DP）与结构信号（3Di）的信息价值最高，分泌系统信号（SE）次之，多序列比对统计（MSA）与功能注释文本（AT）最低。该结论与实验 J 的留一分析相互印证（见 8.6 节）。

### 7.1.5　结果文件与校验要点

实验 A 的结果写入 `results/exp_a.json` 与 `results/exp_a.csv`。校验要点如下。

其一，Baseline 与 Ceiling 的可训练参数量必须相等（均为 10 561）。若二者不等，说明上界臂与基线臂的架构不一致，则 $\Delta_{\text{ASR}}$ 的分母失去意义。

其二，CLEF-ALL 的准确率与 MCC 必须高于全部单模态臂。若出现单模态臂优于全模态臂的情形，则多模态融合环节存在缺陷，须优先排查模态拼接顺序与逐模态归一化。

其三，Ceiling 必须优于 CLEF-ALL。若 Ceiling 不优于 CLEF-ALL，则可能的原因有二：划分泄漏（`train` 与 `ceiling` 重叠）或 `n_ceiling` 规模不足。

## 7.2　实验 B：标注预算扫描

### 7.2.1　命令与目标

```bash
python run_experiment.py B
```

实验 B 的目标为验证"标注越稀缺，预训练增益越大"这一命题，并绘制性能—预算曲线与替代率—预算曲线。其依据来自统计学习理论：一个需要 $O(1/\epsilon^{2})$ 样本才能达到误差 $\epsilon$ 的任务，其额外监督的价值在样本量小时更大，故预期预训练的绝对增益随标注量增加而衰减。

### 7.2.2　实现

实验 B 在标注预算 `n_train ∈ {50, 100, 200}` 三个工作点上重复三臂协议，每个预算跑 `seed ∈ {42, 7}` 两个种子，其余配置同实验 A，但预训练轮数降为 `pre_epochs=30`。结果文件同时记录 `per_cell`（逐单元原始记录）与 `agg`（跨种子聚合）两部分。

跨种子聚合后的实测结果如下表。

| 标注量 $n$ | Baseline ACC | CLEF ACC | Ceiling ACC | Baseline MCC | CLEF MCC | Ceiling MCC | 绝对增益 $\Delta$(MCC) | $\Delta_{\text{ASR}}$(MCC) |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 50 | 0.7750 | 0.8950 | 0.8906 | 0.5599 | 0.7903 | 0.7819 | +0.2304 | 1.05 |
| 100 | 0.8381 | 0.9031 | 0.8906 | 0.6778 | 0.8064 | 0.7819 | +0.1287 | 1.25 |
| 200 | 0.8631 | 0.9050 | 0.8906 | 0.7269 | 0.8102 | 0.7819 | +0.0833 | 1.61 |

表中绝对值增益 $\Delta$(MCC) 为 CLEF 与 Baseline 的 MCC 均值之差。

### 7.2.3　方向性解读

表中出现一个须审慎处理的张力：**绝对增益随标注量单调下降**（+0.2304 → +0.1287 → +0.0833），而 **$\Delta_{\text{ASR}}$ 随标注量上升**（1.05 → 1.25 → 1.61）。二者的方向相反并非矛盾，而是 $\Delta_{\text{ASR}}$ 定义所导致的结构性现象。

其机制如下。$\Delta_{\text{ASR}}$ 的分母为 $M_{\text{Ceil}}-M_{\text{Base}}(n)$。当 $n$ 增大时，基线性能 $M_{\text{Base}}(n)$ 上升（0.5599 → 0.6778 → 0.7269），而上界性能 $M_{\text{Ceil}}$ 基本不变（恒为 0.7819）。故分母随 $n$ 增大而快速收缩（0.2220 → 0.1041 → 0.0550）。与此同时，分子（绝对增益）亦收缩，但收缩速度小于分母，故比值上升。该现象的直接后果为：在高预算端 $\Delta_{\text{ASR}}$ 的"替代比例"语义失效，其取值可超过 1。

因此，实验 B 的正确读法为：**以绝对增益判定"越稀缺杠杆越大"**（该量方向明确、不依赖分母），**以 $\Delta_{\text{ASR}}$ 判定标注节省的等效规模**（该量在低预算端有效，高预算端须谨慎）。该双量并报的做法，正是第五章"数据效率的四种定义"所强调的：任一单一定义均有其适用域与失效域，须交叉印证。

## 7.3　实验 C：VIB 正则化扫描

### 7.3.1　命令与目标

```bash
python run_experiment.py C
```

实验 C 的目标为考察"压缩潜空间是否有益"，即信息瓶颈约束能否提升表征质量。其理论背景为**变分信息瓶颈**（variational information bottleneck，VIB）：在对比损失之外附加一项对潜空间分布的正则，迫使表征在保留任务相关信息的同时压缩冗余信息。**信息瓶颈**（information bottleneck）的核心思想为：一个好的表征应当最大化与标签的互信息，同时最小化与输入的互信息，从而剔除与任务无关的输入细节。

### 7.3.2　实现与结果

实验 C 扫描 $\beta \in \{0.0,\,0.01,\,0.05\}$，其余配置同实验 A（`pre_epochs=30`）。其中 $\beta$ 为 KL 正则项的权重系数，$\beta=0$ 等价于纯 InfoNCE，作为对照。VIB 的优化目标为

$$\mathcal{L}=\mathcal{L}_{\text{InfoNCE}}+\beta\cdot \mathrm{KL}\big(q(z\mid x)\,\big\|\,N(0,I)\big),$$

其中 $\mathrm{KL}$ 为库尔贝克—莱布勒散度（Kullback–Leibler divergence），用于度量变分后验 $q(z\mid x)$ 与标准正态先验之间的差异；$z$ 为潜变量。**潜变量**（latent variable）指模型内部用于压缩输入的隐式表示向量。结果文件额外记录终态 KL 值 `final_kl`，用于度量表征的压缩程度。

实测结果如下表。

| $\beta$ | ACC | MCC | F1 | AUPRC | 终态 KL |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 0.00 | 0.9075 | 0.8146 | 0.9029 | 0.9472 | 0.0 |
| 0.01 | 0.9250 | 0.8519 | 0.9235 | 0.9477 | 30.8243 |
| 0.05 | **0.9375** | **0.8751** | **0.9349** | 0.8542 | 2.3683 |

### 7.3.3　解读

**第一项发现：温和的信息瓶颈确实提升了下游性能。** $\beta=0.05$ 时 ACC 达 0.9375、MCC 达 0.8751，均高于 $\beta=0$ 的对照（0.9075、0.8146）。该结果支持"压缩冗余有助于提升表征的可分性"这一假设。

**第二项发现：终态 KL 随 $\beta$ 的变化并非单调。** $\beta=0.01$ 时终态 KL 高达 30.82，而 $\beta=0.05$ 时反降至 2.37。该非单调性源于 InfoNCE 与 KL 两股力量的博弈：InfoNCE 要求表征保持可分性（倾向于维持较高的后验方差），KL 正则要求表征贴近先验（倾向于压低后验方差）。当 $\beta$ 较小时，KL 项不足以约束后验，故终态 KL 反而偏高；当 $\beta$ 增大到足以主导时，后验被显著压缩，终态 KL 骤降。该现象提示：**终态 KL 并非 $\beta$ 的单调函数，不能以终态 KL 作为"压缩强度"的单一代理量**。

**第三项发现：AUPRC 与 MCC 出现分歧，须如实报告。** $\beta=0.05$ 时 MCC 升至 0.8751，但 AUPRC 反降至 0.8542（低于 $\beta=0$ 的 0.9472）。这说明信息瓶颈的引入在提升阈值化二分类一致性（MCC）的同时，损害了概率排序质量（AUPRC）。该分歧是一项须被诚实保留的负结果：它表明 $\beta=0.05$ 并非在所有指标上一致占优，其适用性依赖于下游任务更看重判别一致性还是概率校准。若下游应用需要可靠的置信度排序（例如按预测概率筛选候选蛋白），则 $\beta=0.05$ 的收益须重新评估。

**校验要点**：确认每个 $\beta$ 下都记录了终态 KL（`results/exp_c.json` 中须有 `final_kl` 字段），否则无法做"压缩程度"的机制分析。

## 7.4　实验 D：模态噪声鲁棒性

### 7.4.1　命令与目标

```bash
python run_experiment.py D
```

实验 D 的目标为考察当模态数据质量下降时 CLEF 的鲁棒性。**模态噪声**在此指叠加在各模态观测上的独立高斯扰动，其强度由缩放因子 `scale` 控制；`scale` 越大表示模态数据越不可靠。

### 7.4.2　实现与结果

实验 D 将噪声缩放因子 `scale ∈ {1, 2, 4}` 乘到各模态的噪声项 $\eta_m$ 上（即 $\eta_m \leftarrow \text{scale}\cdot\eta_m$），其余配置同实验 A（`pre_epochs=30`）。实测结果如下表。

| 噪声缩放 | Baseline ACC | Baseline MCC | CLEF ACC | CLEF MCC | CLEF F1 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 0.8475 | 0.6950 | 0.9075 | 0.8146 | 0.9029 |
| 2 | 0.8475 | 0.6950 | 0.9250 | 0.8496 | 0.9208 |
| 4 | 0.8475 | 0.6950 | 0.9050 | 0.8094 | 0.8989 |

### 7.4.3　解读

**第一项发现（协议正确性检验）：Baseline 在三档噪声下完全不变。** 其 ACC 恒为 0.8475、MCC 恒为 0.6950。该"不变性"本身构成一项重要的协议正确性检验：Baseline 只消费序列通路，与模态通路无关，故模态噪声的任何变化都不应影响其性能。若 Baseline 随模态噪声变化，则说明序列通路与模态通路之间存在意外的耦合（例如二者共享了某个被噪声污染的张量），代码存在缺陷。

**第二项发现：CLEF 在适度噪声下反而略有提升。** `scale=1` 时 CLEF MCC 为 0.8146，`scale=2` 时升至 0.8496，`scale=4` 时回落至 0.8094。该现象与"InfoNCE 具有天然去噪倾向"一致：对比损失要求模型拉近同一对象不同模态的表示，模态间的**共同信号**被保留，而模态特有的噪声在拉近过程中被平均掉，因此适度噪声反而起到了正则作用。该观察与实验 H 中"适度噪声有益"的结论相互印证。

**实践含义**：CLEF 对模态质量的下降具有非平凡的鲁棒性，其性能在噪声放大至 4 倍时仍未跌破 `scale=1` 的水平。这意味着在真实数据中，即便某些模态（如结构预测或功能注释）质量不高，其引入仍可能带来净收益，而非必然损害性能。

# 第八章　边界与稳健性组实验（E–K）的逐条命令解析

边界与稳健性组由 `run_supplementary.py` 驱动，包含实验 E 至实验 K 七组。

```bash
python run_supplementary.py all      # 运行全部七组
python run_supplementary.py E        # 或 E / F / G / H / I / J / K 单跑
```

该组统一使用 `BASE` 全局配置（与实验 A 相同的外层参数），每组实验内部只改变一个维度。其共同目标为刻画主效应结论的适用边界：增益随资源如何衰减（E、F）、对超参数是否敏感（G、H）、在数据缺陷下是否稳健（I、J）、以及结论在统计上是否显著（K）。

## 8.1　实验 E：效率曲线的标度律

### 8.1.1　命令与目标

```bash
python run_supplementary.py E
```

实验 E 的目标为将"增益随标注预算衰减"这一定性判断定量化，即拟合其标度律。**标度律**（scaling law）指某一量随另一量变化所遵循的幂函数关系 $Y=a\,n^{b}$。

### 8.1.2　实现

实验 E 的实现要点如下。标注网格取 `grid = [25, 50, 75, 100, 150, 200, 300]`，共七个工作点，比实验 B 的三点更密。种子取 `seeds = (42, 7, 123)`，共三个。对每个 (种子, 标注量) 单元，分别计算 CLEF 与 Baseline 的 MCC，得绝对增益 `gap_MCC`，并计算标注替代率 `asr_MCC`。随后对每个 $n$ 做跨种子聚合，得 `gap_MCC_mean` 与 `asr_MCC_mean`。最后对聚合后的 $\Delta_{\text{ASR}}$ 做幂律拟合：取对数后

$$\log \Delta_{\text{ASR}}(n)=\log a+b\log n,$$

以最小二乘法（least squares，指最小化残差平方和的参数估计方法）拟合斜率 $b$ 与截距 $\log a$。**决定系数**（coefficient of determination，$R^{2}$）用于度量拟合优度，其定义为 $1-\text{SS}_{\text{res}}/\text{SS}_{\text{tot}}$，取值越接近 1 表示拟合越好。

### 8.1.3　拟合结果的符号说明（一处易混淆的实现细节）

代码中存储的拟合结果为 `a = 0.0691`、`b = -0.6268`。须注意该存储值的符号约定：代码内部以 `b_coef` 表示 `polyfit` 所得的真实斜率，存储时取 `b = -b_coef`，并以 `Δ_ASR = a·n^(-b)` 的形式输出。由于真实斜率 `b_coef` 为正号（$+0.6268$），故存储值 `b` 为负号，而最终表达式中的指数为 `-b = +0.6268`。因此，**正确的拟合关系式为**

$$\Delta_{\text{ASR}}(n)=0.0691\cdot n^{+0.6268},\qquad R^{2}=0.589.$$

该式的指数符号为**正**，即 $\Delta_{\text{ASR}}$ 随标注量 $n$ 单调**上升**。若误将存储值直接作为指数使用（写作 $n^{-0.6268}$），则会得到相反的趋势方向，属实质性错误。

作为辅助量，若改以绝对增益 $\Delta_{\text{MCC}}(n)$ 为拟合对象（由同一批聚合数据另行计算），所得幂律为

$$\Delta_{\text{MCC}}(n)\approx 0.523\cdot n^{-0.430},\qquad R^{2}=0.521,$$

其指数为**负**，即绝对增益随标注量衰减。两个指数方向相反而各自成立，恰好说明"绝对增益"与"归一化替代率"是两个不同的量，必须分别报告。

### 8.1.4　七点实测结果

| 标注量 $n$ | Baseline MCC | CLEF MCC | Ceiling MCC | 绝对增益 $\Delta$(MCC) | $\Delta_{\text{ASR}}$(MCC) |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 25 | 0.6400 | 0.7365 | 0.7839 | +0.0965 | 0.60 |
| 50 | 0.6607 | 0.7813 | 0.7839 | +0.1206 | 0.92 |
| 75 | 0.6835 | 0.7948 | 0.7839 | +0.1114 | 1.14 |
| 100 | 0.7077 | 0.7874 | 0.7839 | +0.0797 | 1.08 |
| 150 | 0.7323 | 0.7788 | 0.7839 | +0.0465 | 0.79 |
| 200 | 0.7455 | 0.8040 | 0.7839 | +0.0584 | 1.44 |
| 300 | 0.7646 | 0.8043 | 0.7839 | +0.0397 | 5.16 |

### 8.1.5　四项发现

**第一项发现：七个工作点全部优于基线。** 绝对增益范围自 $+0.0397$ 至 $+0.1206$，符号全程一致为正，说明主效应在全部预算点上稳健存在。

**第二项发现：绝对增益在 $n=50$ 处达到峰值（$+0.1206$）。** 此处一个有价值的问题是：为何峰值不在最小的 $n=25$ 处。其解释为：当标注量过小时，基线自身亦受方差主导，其性能的低估使增益的测量噪声增大；同时 CLEF 的下游微调在极端稀缺下亦难以充分收敛。两种效应共同作用，使峰值移至 $n=50$ 附近。该现象提示：**"越稀缺杠杆越大"这一命题在小样本端存在一个极值点，而非单调外推**。

**第三项发现：$\Delta_{\text{ASR}}$ 在 $n=300$ 处骤升至 5.16，属分母失效。** 该值伴随极大的标准差（5.35），说明其并非真实的效率提升，而是分母 $M_{\text{Ceil}}-M_{\text{Base}}(n)$ 趋零所致的数值放大。此即第五章所指出的 $\Delta_{\text{ASR}}$ 高预算端失效现象的直接证据。

**第四项发现：$R^{2}=0.589$ 不高，说明纯幂律假设并不成立。** 该值提示增益—预算关系可能存在平台或拐点，而非单一幂律。这是诚实的结论，不应被掩盖；它同时说明，任何基于幂律外推的预测（例如"若标注量为 $X$ 则增益为 $Y$"）都应附带较大的不确定度。

## 8.2　实验 F：无标注池规模缩放

### 8.2.1　命令与目标

```bash
python run_supplementary.py F
```

实验 F 的目标为找出"无标注预训练池需要多大才有效"的下限。**无标注池**（unlabeled pool）指用于对比预训练的无标签样本集合，其规模记为 `n_pool`。

### 8.2.2　实现与结果

实验 F 扫描池规模 `pools = (500, 1000, 2000, 4000, 8000)`，种子取 `(42, 7, 123)`。对每个池规模分别预训练 CLEF，再与同一 Baseline/Ceiling 比较。实测结果如下表。

| 池规模 `n_pool` | Baseline MCC | CLEF MCC | Ceiling MCC | 绝对增益 $\Delta$(MCC) | $\Delta_{\text{ASR}}$(MCC) |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 500 | 0.7180 | 0.6552 | 0.7839 | **−0.0628** | −1.16 |
| 1000 | 0.7180 | 0.7353 | 0.7839 | +0.0173 | 0.23 |
| 2000 | 0.7180 | 0.7563 | 0.7839 | +0.0383 | 0.50 |
| 4000 | 0.7180 | 0.8026 | 0.7839 | +0.0846 | 1.33 |

### 8.2.3　机制与工程含义

**核心发现：池规模为 500 时增益转负。** 该负结果说明：当无标注池过小时，对比预训练不仅无益，反而损害性能。

其机制如下。InfoNCE 的监督信号来自批内负样本之间的区分。当池规模过小时，批内负样本彼此高度相似（因为世界本身的样本总数就少），此时"区分正负样本"退化为一个廉价目标——模型只需捕捉极粗粒度的差异即可降低损失，所学表征未能捕捉细粒度的判别结构，甚至因过度拟合噪声而破坏了原有序列表征中已有的信息。当池规模增至 1000 以上时，批内负样本的多样性上升，对比目标变得有意义，增益转正并随池规模单调上升。

**实践准则**：池规模至少应为批大小的十倍以上。在默认配置下批大小为 256，池规模 4000 对应比值约 15.6，属健康区间；池规模 500 对应比值约 2，明显不足。该准则为一条可直接迁移的工程经验。

**该负结果是全套实验中最具工程价值的一条。** 其原因在于，正结果（"有效"）只告诉使用者方法可用，而负结果（"何时失效"）才界定了方法的适用下限。若忽略此下限而盲目在小池上使用 CLEF，将得到"方法无效"的错误结论。

## 8.3　实验 G：温度参数 $\tau$ 的敏感性

### 8.3.1　命令与目标

```bash
python run_supplementary.py G
```

实验 G 的目标为为 InfoNCE 温度参数的选择提供依据。**温度**（temperature，$\tau$）为 InfoNCE 中 softmax 的缩放系数，其倒数决定了相似度分布的"尖锐程度"：$\tau$ 越小，分布越尖锐，模型对正负样本的区分越激进；$\tau$ 越大，分布越平缓，区分力度越弱。

### 8.3.2　实现与结果

实验 G 扫描 `taus = (0.1, 0.2, 0.5, 1.0)`，种子取 `(42, 7, 123)`，其余配置同 `BASE`。实测结果如下表。

| $\tau$ | ACC | MCC | F1 | AUPRC |
| :-- | :-- | :-- | :-- | :-- |
| 0.1 | 0.8879 | 0.7759 | 0.8864 | 0.9562 |
| 0.2 | 0.8971 | 0.7944 | 0.8955 | 0.9556 |
| 0.5 | 0.9013 | 0.8026 | 0.9001 | **0.9618** |
| 1.0 | **0.9029** | **0.8076** | **0.9045** | 0.9525 |

### 8.3.3　解读

**第一项发现：$\tau=0.1$ 时各项指标最低。** 该结果支持"过小的 $\tau$ 使训练过于激进、稳定性下降"这一判断。

**第二项发现：在本组数据中 MCC 随 $\tau$ 单调上升。** MCC 自 0.7759（$\tau=0.1$）升至 0.8076（$\tau=1.0$），即在 $[0.1, 1.0]$ 区间内 MCC 未出现峰值，而是随 $\tau$ 增大而改善。


**第三项发现：AUPRC 在 $\tau=0.5$ 处达到峰值。** AUPRC 自 0.9562 升至 0.9618（$\tau=0.5$），再降至 0.9525（$\tau=1.0$），呈单峰形态。

两项发现合起来提示：**$\tau$ 的最优值依赖于下游更看重哪一指标**。若以判别一致性（MCC）为准，$\tau$ 应偏大；若以概率排序质量（AUPRC）为准，$\tau$ 取 0.5 更优。在该批数据中，$\tau=0.5$ 是使两项指标同时接近最优的折中点，故默认配置取 $\tau=0.5$ 具有合理性。该结论与部分先验预期（"0.2–0.5 为较优区间"）并不完全一致，其差异须如实报告而非回避。

**实践含义**：$\tau$ 是唯一一个必须手动调节、且不调会显著损害性能的超参数。**超参数**（hyperparameter）指由使用者在训练前设定、而非由训练过程学习的参数。实验 G 的价值在于为 $\tau$ 的取值提供了实证依据，而非依赖经验直觉。

## 8.4　实验 H：表征维度消融

### 8.4.1　命令与目标

```bash
python run_supplementary.py H
```

实验 H 的目标为考察潜变量维度 $d_z$ 对性能的影响。**消融**（ablation）指在保持其他条件不变的前提下移除或改变某一组件，以度量该组件对整体性能的贡献。

### 8.4.2　实现与结果

实验 H 扫描 `dims = (32, 64, 128, 256)`，种子取 `(42, 7, 123)`。每个 $d_z$ 下重建整个世界（因 $d_z$ 决定投影矩阵形状），再重跑 CLEF 与 Baseline。实测结果如下表。

| $d_z$ | 参数量 | CLEF ACC | CLEF MCC | Baseline MCC |
| :-- | :-- | :-- | :-- | :-- |
| 32 | 154 832 | 0.9433 | 0.8869 | 0.8677 |
| 64 | 154 832 | 0.9013 | 0.8026 | 0.7180 |
| 128 | 154 832 | 0.7104 | 0.4256 | 0.3443 |
| 256 | 154 832 | 0.5629 | 0.1354 | 0.1958 |

### 8.4.3　关键警示：该实验的维度耦合问题

**该实验的解释须特别谨慎。** $d_z$ 在本代码中同时改变了三件事：其一，世界潜变量的维度；其二，投影矩阵 $A$、$P_m$ 的形状；其三，噪声维度占总维度的比例（因信号被压缩到少数几个方向，其余维度全为噪声）。它**不改变**编码器参数量（全部 $d_z$ 下 CLEF 参数量恒为 154 832）。

因此"$d_z$ 增大导致性能下降"至少有**两种可能的解释叠加**。

**解释一（世界变难）**：$d_z$ 增大使噪声维度比例上升，任务本身变难，故连 Baseline 都退化（0.8677 → 0.7180 → 0.3443 → 0.1958）。该解释表明这**不是过参数化**，而是难度旋钮被无意中调节了。

**解释二（容量与标注不匹配）**：表征容量增大但标注预算不变（100 条），更适合过拟合，故性能下降。

**原本干净的设计应当是：固定世界（$d_z$ 不变），只改编码器输出维度。** 当前实现将两者耦合。项目选择诚实报告这一张力，同时保留其实践结论（"标注稀缺时应保持保守的表征容量"），因为该建议在两种解释下均成立。

**改造建议**：若要做干净的维度消融，须将 `d_z`（世界维度）与 `out_dim`（编码器输出维度）解耦为两个独立参数。该改造属后续工作，不影响当前结论的实践有效性。

## 8.5　实验 I：训练标签噪声

### 8.5.1　命令与目标

```bash
python run_supplementary.py I
```

实验 I 的目标为考察标签质量差时 CLEF 的优势是否保持。**标签噪声**（label noise）在此指训练标签被按一定比例随机翻转，用以模拟标注者的错误。

### 8.5.2　实现与结果

实验 I 扫描翻转率 `rates = (0.0, 0.05, 0.10, 0.20)`，种子取 `(42, 7, 123)`。核心工具函数如下。

```python
def _noisy(splits, rate, seed):
    rng = np.random.default_rng(seed)
    y = splits["train"]["y_bin"].copy()
    flip = rng.random(y.shape[0]) < rate
    y[flip] = 1 - y[flip]
    return {**splits, "train": {**splits["train"], "y_bin": y}}
```

须注意：**仅翻转训练集标签，验证集与测试集保持干净**。这是标准做法——所模拟的是"标注者犯错"，而非"评测标准本身不确定"。若连测试集也加噪，则无法区分"模型变差"与"评测基准变差"。

实测结果如下表。

| 翻转率 | Baseline MCC | CLEF MCC | 绝对增益 $\Delta$(MCC) |
| :-- | :-- | :-- | :-- |
| 0.00 | 0.7180 | 0.8026 | +0.0846 |
| 0.05 | 0.6777 | 0.7781 | +0.1004 |
| 0.10 | 0.6789 | 0.7867 | +0.1078 |
| 0.20 | 0.6072 | 0.7442 | +0.1370 |

### 8.5.3　解读

**第一项发现：两侧性能均随噪声下降。** Baseline MCC 自 0.7180 降至 0.6072，CLEF MCC 自 0.8026 降至 0.7442，符合预期。

**第二项发现：在本组数据中，CLEF 的优势（绝对增益）随噪声上升而非被侵蚀。** 增益自 $+0.0846$（无噪声）升至 $+0.1370$（翻转率 0.20）。该结果与"对比预训练学到的干净结构会被噪声标签的微调抹掉"这一先验预期方向相反。其可能解释为：对比预训练所提供的表征本身较干净，在微调阶段具有更强的抗噪能力；当标签噪声增大时，Baseline 的微调更快地被噪声主导（其可依赖的仅有 100 条含噪标签），而 CLEF 的表征提供了额外的结构先验，故其优势反而扩大。

**实践建议**：尽管 CLEF 在该设定下表现出抗噪性，仍不应据此认为"更强的预训练可压过噪声标签"。若已知标签质量差，稳妥的做法为**降低微调阶段的拟合强度**（更小学习率、更强权重衰减、更早停止），而非单纯依赖预训练的正则作用。**权重衰减**（weight decay）指在损失中附加参数范数惩罚项，用以抑制参数幅值、降低过拟合。

## 8.7　实验 K：统计显著性检验

### 8.7.1　命令与目标

```bash
python run_supplementary.py K
```

实验 K 的目标为从统计上确认 CLEF 的增益不是偶然。**统计显著性**（statistical significance）指观测到的效应在零假设成立时出现的概率足够低，从而可推断该效应并非由随机波动产生。

### 8.7.2　实现

实验 K 取 `seeds = tuple(range(10))`（0–9 共十个种子），对每个种子跑 Baseline 与 CLEF-ALL，收集配对差异 `diff_MCC` 与 `diff_ACC`。核心检验函数如下。

```python
def _test(diffs):
    d = np.asarray(diffs)
    n = d.size
    mean = d.mean()
    sd = d.std(ddof=1)          # 样本标准差（无偏，分母 n-1）
    se = sd / np.sqrt(n)        # 标准误
    t = mean / se
    # 优先使用 scipy 的配对 t 检验
    p = stats.ttest_rel(clef_list, base_list).pvalue
    # 降级方案：正态近似
    p = 2 * (1 - 0.5 * (1 + erf(abs(t) / sqrt(2))))
    # 自助法 95% 置信区间
    boot = [np.random.choice(d, n, replace=True).mean() for _ in range(20000)]
    ci = np.percentile(boot, [2.5, 97.5])
```

该函数包含三个统计工具。**配对 t 检验**（paired t-test）用于检验同一随机种子下 CLEF 与 Baseline 的差异是否系统性为正；配对而非独立样本检验的理由为：两者共享同一数据划分，配对可消除"划分差异"这一干扰方差，提高检验效力。**标准误**（standard error，SE）指样本均值的标准差，度量均值估计的不确定度。**自助法**（bootstrap）指通过对样本做有放回重采样来估计统计量分布的方法，**置信区间**（confidence interval，CI）指以给定置信水平包含真实参数值的区间。

### 8.7.3　实测结果

MCC 差异的检验结果如下表。

| 统计量 | 数值 |
| :-- | :-- |
| 样本数 $n$ | 10 |
| 平均差异 `mean_diff` | 0.10048 |
| 标准差 `sd` | 0.02927 |
| 标准误 `se` | 0.00926 |
| $t$ 统计量 | 10.8554 |
| $p$ 值 | $1.7998\times 10^{-6}$ |
| 95% 置信区间 | $[0.08404,\ 0.11822]$ |

ACC 差异的检验结果为：`mean_diff = 0.05063`、`sd = 0.01492`、$t = 10.7287$、$p = 1.7998\times 10^{-6}$、95% CI 为 $[0.04225,\ 0.05975]$。

### 8.7.4　三重证据的意义

**第一重：配对 t 检验。** 检验"同一随机种子下 CLEF 与 Baseline 的差异是否系统性为正"。由于两者共享同一数据划分与同一评测集，配对设计可消除划分差异所致的干扰方差，从而在样本量仅为 10 的条件下仍获得较高的检验效力。

**第二重：$p = 1.8\times 10^{-6}$。** 在显著性水平 0.05 下高度显著。其含义为：若零假设成立（CLEF 与 Baseline 无真实差异），则观测到当前或更大差异的概率约为百万分之二。**零假设**（null hypothesis）指"被检验的效应不存在"这一默认假设；**显著性水平**（significance level）指拒绝零假设时所容许的第一类错误概率上限。

**第三重：自助法 95% 置信区间。** 该区间不依赖正态分布假设，属稳健的区间估计。CI 下界 0.08404 > 0，说明增益在最保守的估计下仍为正。该结果用 20 000 次重采样、固定随机种子 20261013 计算，故 CI 本身可复现。

**三项证据的一致性**构成结论可信度的基础：参数检验（t 检验）与非参数检验（自助法）给出方向一致的结论，且置信区间不跨零，排除了"增益由偶然波动产生"的解释。

**注意**：若 `scipy` 未安装，代码会自动降级为正态近似 $p$ 值。在 $n=10$ 时该近似足够准确，但建议安装 `scipy` 以对齐报告口径。**须安装 `scipy` 的理由**：`ttest_rel` 使用的是 $t$ 分布而非正态分布，在小样本下二者有可觉察差异。

## 9.2　`per_cell` 与 `agg` 的区别

每个实验的 JSON 结果都包含 `per_cell` 与 `agg` 两部分，二者的用途不同，不可混用。

`per_cell` 为**每个（参数取值, 随机种子）单元的原始记录**。例如实验 B 的 `per_cell` 包含 6 条记录（3 个预算 × 2 个种子），每条记录含 `seed`、`n_train`、`baseline_ACC`、`baseline_MCC`、`clef_ACC`、`clef_MCC`、`ceiling_ACC`、`ceiling_MCC` 及各 $\Delta_{\text{ASR}}$ 值。

`agg` 为**跨种子聚合后的均值与标准差**，其字段以 `_mean` 与 `_std` 结尾。

**引用数字时应使用 `agg` 的 `_mean` 字段**，因为它已跨种子平均，更稳健；`_std` 字段提供离散程度信息，用于绘制误差棒。`per_cell` 用于做方差分析或离群点排查，例如当某一种子的结果显著偏离其余种子时，可据此定位问题。

**标准差**（standard deviation，SD）在此指同一种子集合内各次独立运行的指标离散程度，它度量的是"随机种子所致的波动"，与实验 K 的置信区间（度量均值估计的不确定度）是不同概念，不可混淆。

# 第十章　迁移到真实数据：四步改造指南

本章给出将合成基准实验迁移到真实蛋白质数据的完整改造路径。迁移的总原则为：**保持训练与评估协议完全不变，只替换数据来源**。该原则之所以可行，是因为代码的层次依赖是单向的——训练层（`train.py`）与评估层（`evaluate.py`）不知道数据来自合成世界还是真实数据，它们只消费"形状正确、语义正确"的张量字典。因此，迁移的全部工作量集中在数据层。

在进入四个步骤之前，须先明确两个核心术语。**同源泄漏**（homology leakage）指测试集中的蛋白与训练集中的蛋白高度同源（例如属同一家族或序列相似度极高），使模型可通过"记住"训练样本而非"学习"判别规律来获得虚高性能；该现象是生物序列任务中最常见、也最危险的评测偏差。**反事实**（counterfactual）指"若某一条件发生改变，结果将为多少"的假设性推断；本项目的上界臂（Ceiling）即是一个反事实上界，回答"若标注不再构成瓶颈，性能将为多少"。

---

## 10.1　第一步：实现真实表征加载

`data.py` 中预留了真实数据加载接口 `load_real_esm_embeddings`。该函数在合成基准复现中不会被调用；若被调用而未提供真实文件，则显式报错，以避免"悄悄用假数据顶替"。其签名与须返回的数据结构如下。

```python
def load_real_esm_embeddings(esm_npz, modality_npz=None,
                             modality_names=MODALITY_ORDER, max_len=None):
    """真实数据接口桩：返回与 SyntheticWorld.sample 同构的字典。

    需要实现的返回（字典）：
      {
        "seq":      (N, seq_len, tok_dim) float32,   # 序列 token 表征（ESM-2 逐残基）
        "mods":     {"DP": (N,20), "MSA": (N,128), "3Di": (N,64),
                     "AT": (N,768), "SE": (N,32)},   # 各模态特征
        "y_bin":    (N,) int,                        # 二分类标签
        "y_class":  (N,) int,                        # 家族/类别标签（用于 ARI/NMI/ASW）
      }
    """
```


该接口的设计意图为：真实数据的加载只需产出一个与合成数据同构的字典，训练层与评估层无需任何改动。**同构**（isomorphic）在此指数据结构在键名、维度与语义上完全对应，从而可被同一套下游代码消费。

实现该函数时，必须保证三件事。

**其一，形状一致。** `seq` 必须是 $(N,\ \text{seq\_len},\ \text{tok\_dim})$ 的三维张量；`mods` 中每个模态的维度必须与 `MODALITY_SPECS` 一致（依次为 20、128、64、768、32）。若真实模态的维度与之不同，须同步修改 `MODALITY_SPECS` 与 `EncoderB` 的 `in_dim`，否则矩阵乘法将因维度不匹配而报错。

**其二，顺序一致。** `mods` 的键顺序必须与 `MODALITY_ORDER` 相同。该要求的重要性在于：模态拼接（`concat_modalities`）按 `MODALITY_ORDER` 的顺序将各模态向量首尾相连，若真实数据的键顺序与之不符，则拼接后的向量中"哪一段对应哪个模态"将发生错位，而模型仍能正常训练（因维度匹配），只是结果不可解释——这类错误不会报错，却会使全部结论失效，属最隐蔽的实现缺陷之一。

**其三，标签一致。** `y_bin` 须为 0/1 整数；`y_class` 须为整数类别标签，供表征诊断指标（ARI、NMI、ASW）使用，可与 `y_bin` 相同。

## 10.2　第二步：生产真实表征

五类模态的生产方式与维度处理如下表。

| 模态 | 生产方法 | 维度处理 |
| :-- | :-- | :-- |
| 序列 token | ESM-2（冻结骨干）逐残基表征，截断/补齐到 `seq_len` | 1280 → 需投影到 `tok_dim`，或改 `tok_dim=1280` |
| DP | 从 MSA 计算 DPC-PSSM | 20 维，直接可用 |
| MSA | MSA 列统计（保守性、熵等） | 需定长（128），可用统计量拼凑 |
| 3Di | Foldseek 结构字母表编码 | 需定长（64） |
| AT | GO 注释 → BioBERT 编码 | 768 维，与 BioBERT 隐藏维度天然一致 |
| SE | DeepSecE 输出 | 32 维，取决于该模型输出层 |

**序列 token 表征**指由蛋白质语言模型（protein language model）逐残基输出的嵌入向量；ESM-2 为其中之一，其隐藏维度为 1280。**逐残基**（per-residue）指对序列中每一个氨基酸位置各产生一个向量，故输出形状为 $(\text{长度}, 1280)$。

须注意：真实模态的维度常常**不能天然对上**合成规格。处理策略有三种。其一，修改 `MODALITY_SPECS` 以适配真实维度（推荐，信息无损）。其二，对真实特征做投影或池化到规定维度（会损失信息，但改动最小）。其三，截断或补零（最差，会引入伪结构，因补零在几何上等价于"该维度恒为某一固定值"，可能被模型误读为真实信号）。

**推荐策略为第一种**：修改 `MODALITY_SPECS` 中的维度字段，使其等于真实模态的实际维度，同时保证 `EncoderB` 的输入维度随之更新。该做法保持信息完整，且改动集中在一处。

真实数据的划分须额外满足三项要求。

**其一，防泄漏。** 同源蛋白（同家族、高序列相似度）必须整族分到同一侧，否则会出现"训练集有近亲、测试集也有近亲"的虚高性能。推荐做法为使用 CD-HIT 按 30% 序列相似度聚类后按簇划分。**CD-HIT** 为一种序列聚类工具，它将相似度高于给定阈值的序列归入同一簇；**按簇划分**（cluster-wise split）指以簇而非以单条序列为划分单位，从而保证同一簇内的近亲全部落在同一侧。

**其二，类别分层。** 训练集、验证集、测试集中的效应蛋白比例应相近，以避免某一划分中正样本极少导致指标不稳。**分层抽样**（stratified sampling）指按目标类别的比例在各划分中分配样本，从而保持各划分的类别分布一致。

**其三，上界臂的独立性。** Ceiling 臂的 1500 条必须与 `train` 的 100 条不重叠。若二者重叠，则上界被高估，$\Delta_{\text{ASR}}$ 的分母失真。该要求与合成世界中的互斥性要求一致（见第三章）。

## 10.5　迁移后必须逐条核对的协议不变清单

迁移时，以下各项必须与合成实验保持完全一致，任何一项的差异都会污染归因。

| 项目 | 具体要求 |
| :-- | :-- |
| 下游分类头结构 | 与 `DownstreamClassifier` 完全相同，参数量一致 |
| 优化器与学习率 | Adam，学习率 $1\times 10^{-3}$ |
| 早停准则 | 验证集 F1，patience = 30 |
| 标准化统计量 | 只使用训练集的均值与标准差 |
| 评测集 | Baseline / CLEF / Ceiling 三臂共享同一测试集 |
| 随机种子控制 | 三处种子分别设定：`world_seed` / `seed` / `data_seed` |
| 指标计算函数 | 统一调用 `classification_metrics` |

**早停**（early stopping）指在验证集指标不再改善时提前终止训练，以避免过拟合；**patience** 指"容忍连续若干轮无改善"的轮数上限。

**标准化统计量**（standardization statistics）指用于将特征缩放到零均值、单位方差的均值与标准差。此处须特别强调：标准化必须只使用训练集的统计量，然后应用到验证集与测试集。若使用全体数据的统计量，则测试集的信息会以统计量的形式渗入训练过程，构成数据泄漏。

## 10.6　迁移中须补足的一项成本

合成实验中，对比预训练阶段的计算开销未被计入成本比较（因合成世界训练极快）。在真实数据迁移中，该项须被补足：跨模态预训练的算力成本应被计入总成本，并与"节省的标注成本"作比较。若预训练算力成本远高于其节省的标注成本，则方法的实际经济性须重新评估。该提醒的意义在于避免"只报告收益、不报告代价"的选择性报告偏差。

# 第十一章　常见坑与故障排查


本章按类别列出复现过程中常见的故障、其成因与排查方向。三类故障的危险程度依次递增：环境类最易发现（直接报错），结果异常类较隐蔽（不报错但数值可疑），方法论类最危险（不报错、数值看似正常、但结论完全失效）。

---

## 11.1　环境类故障

| 症状 | 原因 | 解决 |
| :-- | :-- | :-- |
| `ModuleNotFoundError: torch` | 未安装 PyTorch | `pip install torch --index-url https://download.pytorch.org/whl/cpu` |
| 安装 torch 下载数 GB | 默认拉取了 CUDA 版 | 必须加 `--index-url .../whl/cpu` 指定 CPU 版 |
| 中文图显示方块 | 缺中文字体 | 检查 `style_journal.py` 字体配置；Linux 需安装中文字体 |
| `scipy` 缺失警告 | 未安装 scipy | `pip install scipy`（否则实验 K 使用正态近似 $p$ 值） |

**CUDA** 版与 **CPU** 版的区别在于：CUDA 版包含英伟达 GPU 的加速库，体积达数 GB，但本项目的全部实验设计为 CPU 可运行（默认 `--device cpu`），故安装 CPU 版即可，且可显著减少下载与安装时间。

---

## 11.2　结果异常类故障

| 症状 | 可能原因 | 排查方向 |
| :-- | :-- | :-- |
| Baseline ACC ≈ 0.5 | 难度旋钮未校准（误用了名义值） | 确认 `sigma_seq=13.5`、`eff_shift=6.4`、`signal_scale=8.0` |
| Baseline 随模态噪声变化 | 序列通路与模态通路意外耦合 | 检查 `_frozen_baseline_rep` 是否只消费序列 |
| CLEF 不如 Baseline | 池规模太小或 $\tau$ 不当 | 检查 `n_pool ≥ 1000`、`tau ∈ [0.2, 1.0]` |
| $\Delta_{\text{ASR}}$ 为 inf 或 nan | 分母趋零 | 检查 `annotation_substitution_rate` 的 `1e-8` 保护是否生效 |
| 实验 K 的 $p$ 值异常大 | scipy 未安装，或差异方向不一致 | 安装 scipy；检查 `diff_MCC` 是否系统性为正 |
| Ceiling 不优于 Baseline | 划分泄漏或 ceiling 规模不足 | 检查 `train` 与 `ceiling` 是否重叠 |

须特别说明 **Baseline ACC ≈ 0.5** 一行的成因。报告的**名义难度设定**为 $\sigma_{\text{seq}}=6.0$、$e_{\text{shift}}=1.2$、$f_{\text{shift}}=0.9$，但代码的实际默认值为 $\sigma_{\text{seq}}=13.5$、$e_{\text{shift}}=6.4$、$f_{\text{shift}}=3.5$。二者不同的原因在于：名义值使任务过于容易，Baseline 直接饱和，无法观测到预训练增益；经校准后的实际值使 Baseline 的 ACC 落在约 0.84 的区间，从而留出可观测的增益空间。若使用者误用名义值，将得到 Baseline 接近饱和（或接近随机）的结果，无法复现报告的增益。

---

## 11.3　方法论类故障（最危险）

该类故障的共同特征为：程序不报错，数值看似正常，但结论完全失效。其危险程度最高，故须逐条警惕。

| 坑 | 后果 | 正确做法 |
| :-- | :-- | :-- |
| 标准化用测试集统计量 | 数据泄漏，性能虚高 | 只用训练集的均值与标准差，应用到验证/测试集 |
| 早停后不回滚最优参数 | 早停反而损害性能 | 早停后执行 `load_state_dict(best_state)` |
| `train` 与 `ceiling` 重叠 | 高估上界，$\Delta_{\text{ASR}}$ 失真 | 严格互斥采样 |
| 近源蛋白跨划分 | 虚高（同源泄漏） | 真实数据必须按簇划分 |
| 各臂评测集不同 | 全部比较失去意义 | 所有臂共享同一测试集 |
| 模态顺序不一致 | 模态掩码错位，结果不可解释 | 统一使用 `MODALITY_ORDER` |
| 未固定随机种子 | 结果不可复现 | 三处种子分别设定 |

**"早停后不回滚最优参数"** 一行的机制须作说明。早停的典型实现为：训练过程中持续记录验证集指标，当连续 `patience` 轮无改善时终止；但终止时刻的模型参数已非最优（因最后若干轮无改善），故须回滚到验证集指标最优时刻的参数快照。若不回滚，则早停的收益被抵消，性能反不如不早停。**参数快照**（state dict）指模型全部参数的字典表示，可被保存与恢复。

---

## 11.4　推荐的调试流程

一个高效的调试流程如下。

```
1. 运行 run_experiment.py A（CPU 约 4 分钟）
2. 检查 results/exp_a.json：
   - Baseline MCC 应约为 0.695
   - CLEF-ALL MCC 应约为 0.815
   - Ceiling 参数量应等于 Baseline 参数量（10 561）
3. 若以上全部通过 → 运行完整套实验
4. 若有异常 → 先用 --n_pool 500 快速复现
   （此时 CLEF 应变差，见实验 F），确认管道行为符合预期，再放大规模
```

第 4 步的技巧值得强调。**用小规模快速验证管道**是一种有效的自检手段：实验 F 已确认"池规模 500 时 CLEF 必然变差"，故若使用者在 `--n_pool 500` 下观察到 CLEF **也**变差，则说明"池小则差"这一机制在管道中正确工作；反之，若在该设定下 CLEF 反而变好，则说明管道存在缺陷，须优先排查。该技巧将一条已确证的负结果转化为可执行的正确性检验。

`--mod_mask_frac` 越小，每个模态观测到的潜变量坐标越少，单模态越弱，融合增益越明显；该参数是"多模态红利"的开关。
